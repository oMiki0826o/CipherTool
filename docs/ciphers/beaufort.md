# 博福特密碼（Beaufort Cipher）

> 分類：關鍵字多表替換密碼。CipherTool 參數：非空白、只含英文字母的 `key`；加密與解密使用相同轉換。

## 歷史與維吉尼亞家族的位置

博福特密碼通常與十九世紀英國海軍軍官 Francis Beaufort 的名字連結。它屬於以關鍵字驅動的多表替換家族，外觀看似和維吉尼亞密碼很接近：都把字母轉為零到二十五的數字、都讓 key 反覆提供每一位置的偏移、都只要知道相同 key 就能恢復文字。然而它最重要的差異在減法的方向。維吉尼亞加密是「明文加關鍵字」，博福特則是「關鍵字減明文」。

這個方向差異使標準博福特具有自反性：對密文再做一次相同的 key-minus-text 轉換，便會得到原文。它不像一般維吉尼亞需要分開寫加密、解密公式，因此在紙筆操作時有一點便利；但不要因此誤以為它更安全。key 仍會重複，統計結構依然會在相同週期位置累積，古典分析方法同樣有效。

也要留意名稱混淆。文獻中有標準 Beaufort、variant Beaufort 等相關形式，公式可能不同。本頁只說明 CipherTool 實作的標準「key 減文字」版本。看到其他網站或題目時，先用一小段已知例子確認方向，不要只憑名稱直接套用；一個減號放錯位置，就會得到完全不同的密文。

## 數學表示與自反性

令文字在位置 `i` 的索引為 `Tᵢ`，關鍵字流索引為 `Kᵢ`，採 `A=0` 到 `Z=25`。CipherTool 的加密公式是：

```text
Cᵢ = (Kᵢ - Pᵢ) mod 26
```

再次對 `Cᵢ` 套相同公式：

```text
(Kᵢ - Cᵢ) mod 26
= (Kᵢ - (Kᵢ - Pᵢ)) mod 26
= Pᵢ mod 26
```

因此解密公式與加密公式相同。這個性質不代表「不需要 key」；自反的是操作，不是秘密。沒有正確 key，攻擊者不能直接反轉成原文，只是本密碼的發送者與收件者使用同一程序即可。CipherTool 的 encrypt 與 decrypt 也正因如此呼叫相同的內部轉換。

若 key 長度為 `r`，則 `Kᵢ=key[i mod r]`。和維吉尼亞相同，程式只在 ASCII 英文字母處前進 key 索引；空白、標點、數字、中文與 emoji 原樣保留且不消耗 key。大小寫也會保留，因為大寫和小寫分別在自己的二十六字母範圍中運算。這些格式規則必須被加密與解密雙方完全共享，否則只要一個標點處理不同，後面全部位置就會錯位。

## 手算例子

用 key `KEY` 處理明文 `ABC`。`K=10`、`E=4`、`Y=24`，而 `A=0`、`B=1`、`C=2`：

```text
位置      1   2   3
明文 P     A   B   C
key K      K   E   Y
K - P     10   3  22
密文 C     K   D   W
```

結果是 `KDW`。現在把 `KDW` 當文字、仍用 key `KEY`：`K-K=0→A`，`E-D=1→B`，`Y-W=2→C`，就回到 `ABC`。這個小例子能清楚看見方向：若誤用 `P+K`，第二格會得到 `F`，那是維吉尼亞而不是博福特。

對含格式的輸入，例如以 `KEY` 處理 `A-B`，第一個 `A` 使用 K，連字號保留且不前進，`B` 使用 E。手算時應先把「參與運算的英文字母」抽出來排 key，再把結果放回原位置。常見錯誤是把 key 寫成和全部字元一樣長，導致在空格或標點上多跳一次；另一個錯誤是忘記負數要模二十六化簡，例如 `E(4)-Z(25)=-21`，等價於 5，也就是 `F`。

## CipherTool 操作與輸入限制

在 GUI 選 Classical Cipher → Beaufort Cipher，填入文字與 key，選 encrypt 或 decrypt。兩個模式的輸出對相同輸入和 key 相同，因為此版本是自反的；介面仍保留模式是為了讓所有密碼工具有一致操作方式。key 必須非空、ASCII 且全為字母。`KEY` 和 `key` 在偏移意義上相同；`KEY 1`、空字串、中文 key 或帶連字號的 key 都不被支援。

若你從維吉尼亞頁面複製範例，請不要期待相同密文。兩者共享 key 的循環與格式跳過規則，但核心算式不同。要驗證工具行為，請以 key `KEY` 轉換 `ABC`，確認加密得到 `KDW`，再選解密並確認回到 `ABC`。如果想產生可重現的作業題，應明示使用「標準 Beaufort」及完整 key，並寫出空白標點是否保持；僅說「博福特」在不同資料來源中可能仍有歧義。

## 破解方式與安全限制

博福特不是單表替換，因為同一明文字母會隨 key 位置不同映射成不同密文；但重複 key 讓它仍可被週期分析。攻擊者可用 Kasiski 檢驗找密文重複片段距離的公因數，或以重合指數估計 key 長度。長度猜到後，把同一 key 位置的字元分欄，每欄都是一個固定替換關係，可用字母頻率與語言統計分析。公式方向不同只會改變最後求偏移的計算，不會消除結構性弱點。

已知明文也會直接洩露 key 流：由公式可得 `Kᵢ=Cᵢ+Pᵢ mod 26`。若攻擊者知道密文中某段是固定標題、日期格式或常見問候語，便可能恢復數個 key 字母，再從重複週期推回整把 key。重複使用同一 key 加密多封訊息更糟，因為可供統計的資料量會累積。短密文或長 key 可能增加分析難度，但不是經得起現代攻擊的安全界線。

博福特適合學習模減法、可逆函數與密碼變體的精確定義；它不適合保護任何敏感資料。沒有認證標籤的古典密碼也無法可靠偵測竄改，攻擊者可改動密文某些字元使還原內容改變。若需求是實際機密性與完整性，應使用成熟的現代加密函式庫與經審查協定，而不是疊加博福特、維吉尼亞或編碼。

## 自我檢查

以 key `KEY` 對 `ABC` 執行兩次同一轉換：第一次應為 `KDW`，第二次應回到 `ABC`。再輸入 `A B`，確認空格保持而第二個英文字母使用 key 的第二個字母 E。這兩項測試能檢查自反公式與 CipherTool 的 key 索引規則。

## 和相近方法的比較

把三種常見關鍵字密碼並排，差別會更清楚。維吉尼亞加密為 `P+K`、解密為 `C-K`；標準博福特在兩個方向都用 `K-文字`；某些資料稱為 Variant Beaufort 的形式則可能使用 `P-K` 與相反操作。它們都會使用相同的關鍵字流，所以若只看「key 重複」很容易誤以為可以互通。實際上只要公式方向改變，一串已知答案就完全不同。文件、作業和軟體介面應把版本名稱與公式一同列出，這比只列演算法名稱可靠。

自反性也有一個容易誤解的地方：它不是任何輸入都會不變，而是「以相同 key 對輸出再做一次」才回到原文。以 key `KEY` 處理 `ABC` 得 `KDW`，不是 `ABC`；只有再處理 `KDW` 才回來。ROT13 也是同類概念，但它把 key 固定為十三。這類性質可以減少程式碼中加解密函數的差異，卻不能減少對 key 同步、輸入格式與字母表約定的需求。

若想手算較長句子，建議建立三列：原文、循環 key、索引計算結果。遇到空白與標點時，在 key 列保留空格而不放下一個 key 字母，讓位置一眼可見。完成後再從密文回算一次；因為博福特自反，兩次表格的 key 對齊必須完全相同。這個流程也適合用來除錯：一旦某個位置開始不符，通常是前面非字母多消耗了一個 key，或某次負數取模算錯。

從密碼分析角度，關鍵字週期若恰好是二、三或四等短長度，拆欄後每欄可取得大量字母，頻率分析特別容易。即使 key 很長，若使用者重複拿同一短語、姓名或詞典單字當 key，也可能被猜測。真正的密鑰管理不只要選擇難猜字串，還包括不重複、儲存保護、交換方式與撤銷；古典關鍵字密碼沒有為這些需求提供完整機制。

最後請將博福特輸出視為學習用的密文表示，而非安全封裝。它不會隱藏原文長度與大部分格式，也沒有防止攻擊者替換內容。若只是要驗證傳輸有沒有被改動，可參考完整性工具；若要保密和驗證，則必須使用專為該目的設計的現代方案。
