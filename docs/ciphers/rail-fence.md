# 柵欄密碼（Rail Fence Cipher）

> 分類：置換式密碼。CipherTool 參數：`rails`，必須是至少 2 的整數。

## 歷史與核心觀念

柵欄密碼不替換任何字母，而是改變字母出現的順序。傳統作法將明文沿著多條橫線上下折返書寫，路徑像鋸齒或柵欄；寫完後按每一列由上到下讀出，得到密文。因為字母本身沒有改變，英文中的字母頻率完全保留，改變的是相鄰關係與原始閱讀順序。它是理解置換式密碼與替換式密碼差異最直觀的方法之一。

若 rails 為 3，走法是第一列、第二列、第三列、第二列、第一列，然後重複。以 `WEAREDISCOVEREDFLEEATONCE` 為著名例子，沿三列寫入後，上列讀到 `WECRLTE`，中列讀到 `ERDSOEEFEAOC`，下列讀到 `AIVDEN`，合併為 `WECRLTEERDSOEEFEAOCAIVDEN`。這個例子也提醒我們：不同教材可能會先刪除空格和標點，本工具則保留所有字元並把它們也視為路徑上的一格。

## 路徑、加密與解密

令 rail 數為 `r`，路徑先從 0 增加到 `r-1`，再下降到 0，週期長度為 `2r-2`。對位置 `i`，可用 `i mod (2r-2)` 找到在週期內的位置；超過最底列時，rail 索引以鏡像方式折返。加密不必真的畫表：建立 r 個字串桶，依路徑把每個字元放入桶中，最後由上到下串接。

解密較容易出錯，因為密文已經按列讀出，不能直接再走一次路徑。正確方法是先對原文長度走一遍同樣的鋸齒路徑，只記錄每列會有幾個字元；依這些數量將密文切回各列；最後再次走路徑，每次從對應列取下一個字元，便可交錯還原原文。這是典型的「知道排列規則即可反置換」問題，不需要任何字母反表。

例如以 `HELLOWORLD` 和 3 rails：路徑列為 `0,1,2,1,0,1,2,1,0,1`。上列收 H、O、L，為 `HOL`；中列收 E、L、W、R、D，為 `ELWRD`；下列收 L、O，為 `LO`。密文是 `HOLELWRDLO`。解密時先知道列數量為 3、5、2，切成 `HOL|ELWRD|LO`，再依路徑抽取，即回到 `HELLOWORLD`。

## CipherTool 規則與操作

在 GUI 選 Classical Cipher → Rail Fence Cipher，填入 rails 並選 encrypt 或 decrypt。rails 必須至少二；一列沒有上下折返，不能形成本密碼的意義，因此工具拒絕 0、1 與負數。文字可包含大小寫、空白、數字、標點或中文，全部都會保留並參與重新排序。這與只處理英文字母的替換式工具不同，使用前要特別確認。

空白也會走在鋸齒路徑上，所以若你在加密前自行刪除空格，結果會和直接貼入工具不同。若要重現某個網路範例，必須同時確認它使用的 rails、文字是否去除格式、讀列順序及是否從頂列開始。CipherTool 採最常見的頂列起始、向下再向上折返規則，且不自動補位。

## 破解思路與限制

rail 數通常很小，可直接枚舉二、三、四等候選，解密後以可讀性判斷。即使 rails 不知，密文仍保留原字母頻率與長度；空格若保留，還會直接透露詞界。對長文本，攻擊者可根據常見雙字母、字典分數或已知明文片段比較不同 rail 數的輸出。它沒有 key 空間的現代意義，也沒有隨機性。

更重要的是，任何人只要攔截到密文都能修改某些位置，使收件者得到另一段合法文字，工具並不會警告。柵欄密碼沒有完整性或身分驗證，不能用於密碼、個資、Token、財務資料或私人檔案。它適合作為紙筆解謎、演算法練習與觀察排列如何破壞相鄰字母的教材。

## 常見錯誤與自我檢查

常見錯誤是把行數理解成「每行固定寬度」、忘記最底列後要往上、或解密時把每列切成同樣長度。請以 `HELLOWORLD`／3 rails 驗證輸出 `HOLELWRDLO`，再解密回原文。也請測試 `A B`，確認空白位置會被重新排列而非保留原位。這些檢查能清楚區分柵欄與一般表格轉置。

## 延伸理解

置換密碼的安全直覺常被「字母都還在」低估。若原文是英文，字母頻率不變，這確實讓分析有線索；但相鄰關係被打散後，直接閱讀仍可能困難。古典密碼常把替換與置換結合，試圖同時隱藏頻率與順序；然而如果規則固定且 key 小，現代分析仍能還原。Rail Fence 的教育意義正是用最小規則展示這兩種轉換層次。

從程式實作看，空字串、很短的字串與 rail 數大於文字長度都是值得測試的邊界。正確程式應仍能返回可逆結果，而不是越界或遺失字元。CipherTool 不靠補 X 或填充符號，因此解密後應逐字回復原輸入；若輸出不同，先檢查 rails 與原始格式是否完全相同。

## 更深入的手算與分析

三列只是一個好畫的起點，不是唯一規則。rail 數四時，路徑為 0、1、2、3、2、1，再回到 0；週期由四變成六。rails 越多，文字在各列分布越稀疏，密文的排列越不直觀，但 key 仍只是一個小整數。若文字長度已知，攻擊者通常只需嘗試到合理上限，並以英文常見字串或詞典分數選出候選結果。

解密時可以先在紙上畫出與原文同樣多的空格，沿鋸齒路徑在每個格子標上列號。然後依各列空格數將密文分段填回，再沿原路徑讀。這種「先畫形狀、不先填字母」的方法能避免列長估錯。對教學而言，它也清楚說明加密讀的是列、解密讀的是路徑，兩步恰好互逆。

柵欄密碼有時被誤稱為「把文字上下排就加密了」。實際上起始方向、rail 數、是否包含空白、是否保留換行都屬於規格。若加密端把空白算入，解密端卻先刪掉空白，路徑位置便不同，後面所有字元都會錯。這種格式同步問題與真正的串流處理很相似，因此值得在練習中刻意測試。

它也不會改變資料量。密文長度和原文完全相同，沒有隨機填充、沒有訊息認證碼，攻擊者可據此判斷原文長度並直接竄改。把 rail 數寫在密文旁或藏在檔名中，當然更沒有任何保密效果。學習時可以享受它的視覺規律，實務上則應使用成熟的安全封裝格式。

若題目只給出密文與「fence」提示，先嘗試 rails 2 到 6 並保留原有空格，常能快速找出候選；但不要以某一個可讀單字就判定答案，應檢查整段是否自然且能以同一 rails 重新加密回原密文。這是解謎中驗證假設的基本方法。

rails 取二時，路徑只是上下交替，密文先收所有偶數位置再收所有奇數位置；這是理解最小有效欄數的好起點。rails 增加後，中間列在一個週期中被造訪兩次、頂底列各一次，所以每列長度不平均。把這個分布先畫出來，就能理解解密為何不能平均切密文。

若原文長度小於 rails，仍可以定義路徑，只是部分列沒有字元；程式應保持可逆而不需補位。這和「rails 必須小於文字長度」不同，後者只是某些手算教材為了圖形好看而加的限制。CipherTool 真正拒絕的只有小於二的 rail 數。

柵欄密文由不同列的連續片段組成，這是攻擊者可利用的結構。若已知明文開頭，便可推測它落在頂列的哪些位置；若有多封同 rails 訊息，列長分布更容易被比較。這些都是它只適合練習的具體原因。
