# 卡馬蘇特拉密碼（Kamasutra Cipher）

> 分類：成對互換的單表替換密碼。CipherTool 參數：13 組以逗號分隔、完整覆蓋 A–Z 的 `pairs`。

## 名稱與歷史背景

卡馬蘇特拉密碼的名稱來自古印度《欲經》（Kama Sutra）中關於女性應學習的技藝之相關記載，因此也常被稱為 Kama Sutra cipher。它的核心非常簡潔：將字母隨機兩兩分組，每個字母都只和其配對對象互換。若 A 與 M 一組，A 加密為 M，M 加密也為 A；若 B 與 X 一組，B 與 X 彼此交換。二十六個英文字母正好形成十三組。

它和 Atbash、ROT13 一樣具有自反性，也就是同一操作做兩次會回到原文；不同之處在於 Atbash 和 ROT13 的配對固定，卡馬蘇特拉可由使用者決定任意的十三對。歷史故事常把它描述為隱私保護的簡易技巧，但從現代觀點看，它仍是非常弱的固定替換。它的價值在於展示「一個排列可以由互換對組成」的數學結構，以及自反性如何讓加密和解密共用程序。

請注意名稱本身不保證全世界都採同一組配對。有些教材會列出預設表，有些要求由雙方事先隨機決定。本工具不假定任何內建預設，必須明確輸入完整 pairs，這讓結果可重現，也避免使用者以為某個網路範例一定與程式一致。

## 配對表與數學表示

一張合法表必須把 A 到 Z 每個字母恰好放入一次，組成十三組兩字母的 pair。示例：

```text
AM,BX,CQ,DW,ET,FR,GS,HL,IO,JP,KN,UV,YZ
```

逗號分隔各組，組內先後順序不影響結果：`AM` 和 `MA` 都表示 A、M 互換；組與組的順序也不影響映射。令這個替換函數為 `f`，每一對 `(x,y)` 滿足 `f(x)=y`、`f(y)=x`。因此：

```text
f(f(x)) = x
```

在排列理論中，這稱為由十三個不相交二循環（transpositions）構成的對合排列。因為沒有任何字母固定不動，也沒有三個以上的循環，表的形式非常受限。若某字母出現在兩組，例如 `AM,AB`，A 對誰就不再唯一；若少一個字母，則那個字母無法轉換。CipherTool 會檢查組數必須是十三、每組剛好兩個字母、所有字母集合剛好等於 A–Z，否則拒絕。

## 加密、解密與格式行為

以示例表處理 `CAT`：C 對 Q、A 對 M、T 對 E，因此密文是 `QME`。再對 `QME` 套用完全相同的表：Q 對 C、M 對 A、E 對 T，回到 `CAT`。不需要計算反表或切換模式，因為這個表自己的反函數就是自己。

CipherTool 在替換前將每個 ASCII 英文字母轉成大寫，因此輸入 `Cat` 輸出也是 `QME`，不保留原始大小寫。空格、標點、數字、中文和 emoji 不屬於英文對照表，會原樣保留；例如 `A-1` 在示例表下輸出 `M-1`。這一點和某些其他工具不同：它不是拒絕標點，也不是把小寫留在小寫。若你要求逐字保留大小寫，必須在使用前後自行記錄格式，因為目前實作的公開規則是統一輸出大寫英文字母。

手算最常見錯誤是把 pair 當成單向箭頭，例如只記 A→M 卻忘了 M→A；那會讓解密失敗。第二個錯誤是偷用一組不完整的「好記」配對，或重複某字母但沒注意到漏掉其他字母。最穩妥方法是先將 pairs 寫成兩欄完整對照表，逐一勾掉所有 A–Z；若每字母正好出現一次，便可放心使用。

## 在 CipherTool 中使用

選擇 Classical Cipher → Kamasutra Cipher，在參數欄輸入完整配對表。可加入逗號旁的空白，例如 `AM, BX, CQ, ...`；程式會忽略每組外圍空白並轉為大寫。不要把配對表寫成 `A=M`、用空格取代逗號、或加入只有一個字母的組，這些都不符合格式。選 encrypt 或 decrypt 的結果相同，因為內部都呼叫同一個雙向替換操作。

使用前先以短測試驗證輸入表。例如用前述示例表，`A` 應變 `M`，`M` 應變 `A`，`CAT` 應變 `QME`。若 `A` 再次出現在第二組，工具應立即報錯；這是避免不可逆映射的重要保護。若你要與他人交換訊息，配對表就是全部秘密，必須透過安全方式協調；將它和密文寫在同一篇公開訊息中，就等於沒有保密。

## 破解思路與現代限制

雖然配對方式的數量不少，密碼仍屬單表替換。同一明文字母永遠對同一個密文，且每個映射還必須成對對稱，這反而給攻擊者更多結構。頻率分析能猜出常見字母；已知一個明密文字母對就同時知道反向關係；常見單字模式和保留的空格、標點也能快速縮小候選。長密文可用字典、n-gram 統計與排列搜尋破解，不必枚舉所有可能配對。

它的自反性也不等於安全。加密和解密相同只是便利性，沒有增加密鑰熵、沒有隨機化、沒有防竄改，也沒有驗證收件者身分。若攻擊者修改密文一個字母，收件者會得到另一個合法字母，工具不會知道內容被改過。把它和 ROT13、Atbash 或 Base64 疊加通常只創造更多公開可逆步驟，不會建立現代機密性。

本密碼適合用來學習對合排列、參數驗證與古典頻率分析，不適合保護任何敏感內容。密碼、個資、恢復碼、API token、商業檔案與私人對話都需要成熟的現代認證加密方案。若目標只是解謎或課堂活動，請把配對表、大小寫規則與非字母處理明確寫在題目中。

## 延伸練習與自我檢查

將 pairs 中每組的順序與組順序打亂，應得到相同輸出，因為映射本質沒有改變。然後將一個字母重複，例如把 `AM` 和 `BX` 改為 `AM,AX`，工具應拒絕，因為 B 遺失而 A 重複。最後以合法表對任何英文串執行兩次，加上空格與標點也應保留原位置、字母則回到同一個大寫結果。這些測試同時確認二循環、自反性與輸入驗證。

## 進一步理解與使用界線

成對互換可視為最簡單的可逆置換之一。一般單表替換允許一個長循環，例如 A 變 B、B 變 C、C 變 A；卡馬蘇特拉限制所有循環長度都只能是二，因此套用一次與兩次的行為格外容易驗證。這項限制也縮小了可選表的數量，並讓已知一組對應的攻擊者同時知道兩個方向。它很適合演示「可逆」是數學性質，不是安全等級。

設計練習時，請避免將配對表用可預測的字母表前後配對，否則它會退化成接近 Atbash 的公開規則。即使是隨機配對，也只能增加解題工作，不能對抗有足夠密文的統計分析。更長的訊息會讓英文字母頻率更穩定，反而常使攻擊更容易；短訊息看似難猜，也只是因為樣本不足，並沒有可依賴的密碼學保證。

程式對非 ASCII 英文字母保留原樣，所以 `A中文B` 仍能讓 A、B 互換。這方便保留句子格式，卻會把中文和標點完全暴露。若傳遞內容包含需要保密的任何部分，不能只保護其中的英文字母再稱為加密。資料保護的範圍必須涵蓋整份資料，而不只是看起來最像文字的欄位。

作業驗收可再加入「表是否完整」的測試：把十三組展開、排序後應剛好是 `ABCDEFGHIJKLMNOPQRSTUVWXYZ`。這個簡單檢查比加密幾個單字更能證明 key 合法，也說明為何工具必須在開始轉換前驗證參數。
