# 卡爾達諾格欄（Cardano Grille）

> 分類：旋轉遮罩／隱寫式格欄模擬。CipherTool 使用固定 4×4 孔位與四次順時針旋轉，不提供自訂格欄。

## 歷史與核心概念

Cardano grille 以十六世紀的 Girolamo Cardano 命名。發信者把挖有孔洞的紙板覆在空白紙上，只在孔洞中寫下秘密字母，再移開紙板，以看似自然的內容填滿其他位置；收件者以相同格欄覆蓋，才能讀出訊息。這較接近隱寫術：目標是讓旁觀者不注意到秘密存在，而不只是把每個字母換成另一個符號。

CipherTool 採固定 4×4 旋轉格欄。初始孔位是 `(0,0)、(0,1)、(0,2)、(1,1)`，每寫四個字母後將格欄順時針旋轉，總共四個方向剛好覆蓋十六格。程式先保留英文字母、轉成大寫，J 不特別合併；不足十六字的最後區塊以 X 補齊。它輸出的不是自然偽裝信，而是按固定格欄讀出的十六字母區塊，因此是格欄排列的教學模擬。

## 加解密與使用限制

加密時，明文依旋轉後的孔位寫入 4×4 格，再逐列讀出全部十六格；解密反過來先把密文逐列填回格，再依同一孔位與旋轉順序取出秘密字母。密文長度必須是十六的倍數，否則無法分成完整方格。解密不會自動移除 X，因為原文可能真的含 X；應由使用者依訊息語意判斷末尾填充。

這種固定格欄沒有秘密孔位，任何知道本頁規則的人都能重建。即使使用自訂孔位，若格欄本身被截獲或重複使用，內容仍可被還原。它也不會生成用於掩護的自然語言，不能把密文外觀當成隱寫成功。合適用途是學習旋轉座標、方格排列與「隱藏存在」和「加密內容」的差別；不適合敏感資料。

## 自我檢查

輸入少於十六個英文字母時，密文仍應為十六字元；解密可得到大寫原文加上 X。輸入含標點或中文時，這些字元會被忽略。請確認這些正規化規則後再比對任何手算答案。

## 旋轉座標如何覆蓋整張方格

四乘四格以左上角為 `(0,0)`。一次順時針九十度旋轉可寫成 `(row,column)→(column,3-row)`。初始四孔旋轉四次後會落到十六個互不重疊的位置；這正是合格旋轉格欄的條件：每格在四個方向中恰好被一個孔覆蓋一次。若自訂孔位在旋轉後重疊，某些格會被寫兩次而另一些永遠空白；若有遺漏，同樣不能承載完整十六字元。因此格欄設計本身也是一個組合與座標問題。

CipherTool 固定初始孔位，代表使用者不需要手動畫紙板，也不能誤選無效遮罩。加密時每四個字母填入目前孔位，旋轉後繼續；四輪完成後逐列讀出矩陣。解密時先把十六個密文字元逐列放回，然後在相同輪次、相同孔位順序讀取。只要旋轉方向或起始方向不同，輸出就完全不同，所以題目若採逆時針或另一組孔位，不能直接套用工具。

## 隱寫術和加密的界線

手工 Cardano grille 的經典使用法是在孔洞中寫秘密，再以普通語句填滿其餘格子。旁觀者若不知格欄存在，可能不會注意到秘密；即使看到載體文字，也不一定能確定哪些位置重要。這是「隱藏訊息存在」的策略。CipherTool 則輸出十六字母密文區塊，沒有生成自然的掩護文字，因此只演示位置置換，沒有完成隱寫載體那一半。

即使有人自行把輸出混入文章，也要注意自然語言填充很難做得毫無痕跡，且數位平台可能改變換行、字距或版面，使孔位不再對齊。真實資料保密更不能依賴旁觀者沒有發現；應使用公開可審查的現代加密。格欄在教材中最有價值的是讓人看見「可讀外觀」與「安全機制」是兩件不同的事。

## 填充與除錯

每個區塊都必定十六字母，因此 1 字母和 16 字母輸入都輸出 16 字元，17 字母則輸出 32 字元。末尾 X 是補位，不應自動刪除；原文若本來以 X 結尾，程式無法區分。手算除錯可先用 `ABCDEFGHIJKLMNOP`，因為每格唯一，解密後最容易看出旋轉順序或讀列方向是否錯誤。接著再試較短文字觀察 X 的行為。

固定格欄沒有保密 key，且英文字母正規化會遺失大小寫與非字母。它不能保護帳號、密碼或文件，只適合歷史、座標旋轉與隱寫概念練習。

若要用紙筆複現本工具，先畫 4×4 格並在初始四孔位置寫入前四個字母；依座標公式轉九十度，寫下一批四字母，直到十六格填滿，最後橫向抄出。解密則先橫向填格，再以相同孔位順序抄取。以連續 `ABCDEFGHIJKLMNOP` 做測試特別好，因為每一格都能辨識，任何旋轉方向錯誤都會立即顯示。

格欄的「孔洞」在實體世界是秘密物件，但數位工具中固定孔位已寫在程式規則裡。因此它不是使用者自訂的 key。這也是教材必須把固定設計說清楚的原因：隱寫或加密是否安全，取決於敵手知道哪些資訊，而非名稱聽起來是否神祕。

格欄也說明「填滿矩陣」和「讀取矩陣」是兩個獨立步驟。加密端以孔洞順序寫入而以列順序讀出；解密端以列順序填入而以孔洞順序讀出。若手算結果不符，先判斷錯誤發生在寫入、旋轉還是讀取，而不要同時改動三個規則。這種分步驗證同樣適用於其他轉置密碼。

在安全討論中，格欄最值得保留的是隱寫觀念：即使內容加密，明顯的密文外觀仍可能引起注意；反過來，即使內容藏得不明顯，一旦被抽取也未必有保密性。兩者可以結合，但都必須獨立評估。本工具只展示前者的幾何讀寫，不承諾完整隱寫系統。

本工具每個區塊的輸出長度固定十六，這也會洩露正規化後字母數落在某個十六字範圍內。填充讓最後區塊完整，卻不隱藏訊息大致長度。若手算時看到少於十六字的輸出，代表你可能只抄了孔洞字母，忘了加密步驟最後需要讀出整個方格。

旋轉的方向與方格座標系是規格的一部分。紙上若把列由下往上編號，或從右上角當原點，即使說「順時針」也可能得到不同孔位。使用 `(row,column)` 和本頁的旋轉式能消除這種視覺歧義，這也是程式模擬比口述規則可驗證的原因。

格欄的孔位在每次旋轉後應被視為一套新的寫入座標，而不是把紙上已寫的字母旋轉。實體操作中旋轉的是遮罩，紙張與字母位置不動；在程式模型中同樣是改變選取的位置。分清這一點可避免把矩陣整體旋轉而得到錯誤密文。

固定 4×4 設計也讓區塊邊界完全可預測；兩封訊息若從各自第一格開始加密，並不會共享任何跨區塊狀態。這便於教學驗證，卻不增加安全性。
