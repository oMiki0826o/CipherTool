# 普萊費爾密碼（Playfair Cipher）

> 分類：雙字母替換密碼。CipherTool 參數：`keyword`；採 5×5 方格、I/J 合併、X 補位（若原字母是 X 則以 Q 補位）。

## 歷史與為何一次處理兩個字母

普萊費爾密碼以 Charles Wheatstone 的設計及 Lord Playfair 的推廣聞名，是十九世紀很重要的手工密碼。它不像單表替換逐字更換，而是把文字拆成二字母組（digraph），並在一張由 keyword 排列的五乘五方格中依相對位置轉換。因為英文最常見的統計特徵不只存在於單一字母，也存在於 `TH`、`HE`、`IN` 等字母對，改以 digraph 操作能比單字母替換更有效地破壞簡單頻率關係。

歷史上的版本與使用規範不完全一致，尤其 I/J 合併、填充字母與格式清除方式常不同。CipherTool 的實作是明確的：只保留英文字母、轉成大寫、將 J 改成 I，再以 keyword 的不重複字母先填方格，最後補上剩餘 A–Z（不含 J）。這是可重現的教育版本，不應假定能直接解出使用其他約定的題目。

## 建立方格與分組

以 keyword `MONARCHY` 為例，先保留不重複字母 `M O N A R C H Y`，再補上尚未出現的字母，得到：

```text
M O N A R
C H Y B D
E F G I K
L P Q S T
U V W X Z
```

明文必須分成沒有相同兩字母的組。若一組候選是 `LL`，會插入補位字母，將它變成 `LX`，第二個 L 再與下一字母重新配對；若原字母本身是 X，工具改插 Q，避免形成 `XX` 後仍不合法。文字最後若剩一個字母，也補 X。這些補位是為了讓每一組能套用方格規則，因此解密後不會由工具自動刪除：你必須依語意判斷某個 X 或 Q 是原文還是填充。

## 三條加密規則與反向解密

對一組字母 `(a,b)`，先找它們在方格的行列。若同一行，加密時兩者各向右一格、超出右端便繞回該行左端；若同一列，各向下一格、超出底端便繞回頂端；若不同列也不同欄，便取同一矩形的另外兩角：第一字母改成它所在行、第二字母所在欄的位置，第二字母反之。解密完全反向：同一行向左、同一列向上、矩形規則不變。

例如在上表中 `HI` 分別位於第二行第二欄與第三行第四欄，形成矩形，輸出第二行第四欄的 B 與第三行第二欄的 F，即 `BF`。若同一行的 `AR`，加密為 `RM`；若同一列的 `ME`，加密為 `CL`。矩形規則之所以能可逆，是因為以相同兩列兩欄交換角落，做兩次又回到原座標。

## CipherTool 的精確行為

keyword 可以是空字串，空 key 時方格就是按 A 到 Z（I/J 合併）排列；keyword 中的非英文字母會在正規化時被略過。明文和密文也會移除空白、標點、數字與中文，並統一輸出大寫。因此 `Hide, Jolly!` 不會保留原格式，且 J 變 I。解密前的英文字母數量必須是偶數，否則工具會報錯；因為它無法將奇數長度密文拆成完整 digraph。

在 GUI 選 Classical Cipher → Playfair Cipher，輸入文字與 keyword，選 encrypt 或 decrypt。隨機參數功能會產生一個八字母 key，方便建立不同方格。若需重現結果，必須保存完整 keyword 與本頁的 I/J、補位規則；只說「用 Playfair」不足以重建相同密文。

## 破解與限制

Playfair 的 digraph 統計比單字母替換難處理，但仍可被分析。密文長度為偶數、相同字母不會在同一原文 pair 中直接出現、以及方格中鄰近關係都提供結構。攻擊者可用已知明文、猜測常見詞組、digraph 頻率與爬山搜尋調整方格排列。第一次世界大戰後，隨著更強的分析技術與機械化密碼出現，它已不具實際安全性。

它也不保留原始格式，且填充字母造成解密結果可能有歧義：`BALLOON` 類文字會得到含插入 X 的還原串，不能由程式確定哪一個 X 應刪除。這對自然語言謎題通常可由詞意解決，對資料檔案、密碼或精確機器資料則不可接受。它沒有認證或防竄改功能，更不能取代現代加密。

## 自我檢查

用 `MONARCHY` 加密 `HIDE THE GOLD`，先確認所有非字母被移除、J/I 合併、分組與補位符合規則；再用同 key 解密，結果可能含 X 或 Q，應依分組規則判讀。另測試奇數長度密文解密，工具必須拒絕。這些測試比只比對一串答案更能驗證方格、分組與反向移動都正確。

## 學習重點

普萊費爾展示了密碼設計如何從單字母統計轉向成對統計，也展示了格式正規化的代價。它的規則看似繁多，但都可化為方格座標上的局部移動；手算時先畫方格、再標示每一對的位置，比背口訣可靠。理解它後，再學 Hill 的矩陣分組會更自然：兩者都不再把「一個字母」當成唯一操作單位，但安全性仍遠不足以應付現代需求。

## 分組演算法的細節

CipherTool 的分組不是簡單把字串每兩個切開。它由左往右檢查：取第一字母後嘗試取下一字母；若兩者相同，就只消耗第一字母並插入補位，第二個相同字母會在下一輪成為新 pair 的開頭。以 `BALLOON` 為例，正規化為 `BALLOON`，分組是 `BA LX LO ON`，不是 `BA LL OO N`。末尾單獨 N 再補成 `NX`。若文本是 `XXXX`，第一個 X 遇到第二個 X 時會插入 Q，避免產生仍相同的 `XX`；這個特殊規則是本工具的實作細節，其他教材不一定相同。

解密並不重新分組或插入補位，而是要求密文已是偶數個英文字母，直接兩兩套反向方格規則。這就是為何加密可接受任意長度英文字母，解密卻拒絕奇數長度。解密得到的 `BALXLOON` 或末尾 `X` 必須由讀者根據語言上下文判斷；程式若任意刪除所有 X，會把原本真正的 X（如 `EXTRA`）破壞掉。這種不可避免的歧義說明它只能用於人類可判讀的文字，不適合資料完整性要求嚴格的場景。

## 方格座標的除錯方式

遇到結果不符時，先不要重算整段。先列出 keyword 去重後的序列，確認 J 是否已改為 I，再核對方格是否逐列填入。接著只選一個 pair：若同列，確認加密是向右不是向下；若同欄，確認是向下不是向右；若是矩形，確認第一個輸出保留第一個字母的行、使用第二個字母的欄。三種規則中，矩形不依 direction 改變，因為同一對角交換本身就是反向操作。

可用 keyword 空字串作除錯基準。此時方格是普通 A 到 Z（略 J），容易手算座標；確認核心規則後再加入 keyword。keyword 中的重複字母只保留第一次，且非英文字母被忽略，因此 `MON-ARCHY` 和 `MONARCHY` 在本工具中建立相同方格。若題目要求將符號或數字納入方格，便不是此實作可直接處理的設定。

## 密碼分析的具體線索

Playfair 密文會以偶數長度呈現，且加密前消除了同一 pair 的重複字母；這些格式特徵能縮小攻擊者的假設空間。常見 digraph、可能單詞片段、已知開頭與不同訊息重複使用同一 key 都可用來約束方格中相對位置。手工分析可能很費工，但現代電腦能以英文四字母組分數評估候選方格，反覆交換格內字母來搜尋更合理的明文。

keyword 不是防止這些攻擊的萬靈丹。人類常選的單字、地名或短語會讓方格排列可被字典猜測；即使 keyword 隨機，算法的固定 5×5 結構仍可受足夠密文分析。它也不包含隨機值或訊息驗證，攻擊者可修改密文 pair 而使解密文字改變。這些限制正好提醒我們：比單表替換複雜不等於足以處理現代威脅。

## 延伸練習

用 `MONARCHY` 建方格，手算 `HI` 應得 `BF`，再手算解回 HI。接著比較 `BALLOON` 和 `BALXLOON` 的加密前分組，觀察為何人類需要判讀填充字母。最後把同一段文字分別交給 Playfair、Rail Fence 與 Hill，記錄哪些保留格式、哪些改變字母值、哪些需要補位；這比單獨記住每個名稱更能建立密碼分類概念。
