# Autokey 密碼（明文自動密鑰）

> 分類：以明文延長 key 流的多表替換密碼。CipherTool 參數：非空白、只含英文字母的種子 `key`。

## 歷史定位與名稱的意思

Autokey 是維吉尼亞家族的重要變體，中文常譯為自動密鑰或自動關鍵字密碼。它的目的很明確：一般維吉尼亞會無限重複一小段 key，重複週期容易被 Kasiski 檢驗或重合指數找出；Autokey 則只用一段短的起始 key，接下來把明文本身接到 key 流後面。這使 key 流不再以固定短週期重複，同一份明文的自然變化會延伸到後續加密位置。

歷史上，這類概念與文藝復興時期的密碼設計者 Cardano 和 Vigenère 等人的工作常被一同討論。名稱容易造成誤會：它不是工具替你隨機產生或自動保存安全 key，而是演算法把資料的一部分拿來當後續位移。這個設計在對抗簡單的重複 key 分析時有所改進，卻也引入新的弱點：已知或猜中的前段明文會讓後續 key 流跟著暴露，而且錯一個字元可能讓整段解密失去同步。

CipherTool 實作的是「明文 Autokey」版本，而不是使用密文延長的 ciphertext-autokey 變體。這個區別必須先寫清楚：兩種版本的 key 流不同，不能互相解密。本頁描述的規則是先放種子 key，然後依序接上先前出現的明文字母索引。

## 金鑰流與數學公式

令種子 key 的長度為 `s`，明文英文字母索引序列為 `P₀, P₁, …`。將 key 流記為 `Kᵢ`。前 `s` 個位置使用種子字母；之後使用前面的明文字母：

```text
Kᵢ = seed[i]                 （i < s）
Kᵢ = Pᵢ₋ₛ                    （i ≥ s）
Cᵢ = (Pᵢ + Kᵢ) mod 26
```

解密表面上仍是 `Pᵢ=(Cᵢ-Kᵢ) mod 26`，但關鍵在於後半段 `Kᵢ` 來自先前的**已還原明文**。因此解密必須由左到右進行：先用 seed 解出前幾個字母，把它們存起來，再把這些剛求出的明文當作下一格 key。不能像一般重複 key 維吉尼亞一樣，先把完整 key 預先寫好，因為解密前你還不知道它的後半段。

CipherTool 只將 ASCII 英文字母放入明文索引序列。空白、標點、數字、中文與其他非字母會原樣保留，也不會占用 seed 或明文 key 流的位置。大小寫同樣保留，但計算使用對應的 A 到 Z 偏移。這個規則意味著文句中的格式不會改變 key 對齊；如果另一個工具把逗號也算成一格，兩邊會從那裡起得到不同結果。

## 完整手算例子

選種子 key `QUEENLY`，明文 `ATTACKATDAWN`。種子長度是七，所以前七格用 `Q U E E N L Y`，之後接上明文最前面的 `A T T A C`：

```text
明文：A T T A C K A T D A W N
key流：Q U E E N L Y A T T A C
密文：Q N X E P V Y T M T C P
```

第一格 `A(0)+Q(16)=Q`；第二格 `T(19)+U(20)=39 mod 26=13=N`；第八格明文 `T` 不再使用 seed 的第一格，而使用第一个已存在的明文字母 `A`，所以維持 `T`。這裡最能看出和重複 key 維吉尼亞的差異：若循環 `QUEENLY`，第八格會用 `Q`，密文就不同。

解密 `QNXEPVYTM TCP`（省略空格僅為閱讀）時，先用 `QUEENLY` 得到前七個 `ATTACKA`。第八格 key 已不是 Q，而是剛解出的第一個 `A`，因此 `T-A=T`；第九格使用第二個 `T`，依序重建。若在第三格把一個字母讀錯，之後用來延長 key 的明文也錯，錯誤會向後傳播。這稱為錯誤擴散，是使用明文回饋的直接結果。

## 在 CipherTool 中操作

於 GUI 選 Classical Cipher → Autokey Cipher，輸入文字和 seed key，再選 encrypt 或 decrypt。key 的驗證規則與維吉尼亞相同：不可空白、必須是 ASCII 英文字母；`QUEENLY` 可用，`QUEEN LY`、`KEY2`、`中文` 不可用。程式在加密時累積明文偏移，在解密時累積剛還原的明文偏移，這兩條流程看似相似，卻不能互換。

建議先用短例子驗證：以 key `B` 加密 `ABC`。第一格使用 B，`A→B`；第二格使用前一個明文 A，所以 `B→B`；第三格使用前一個明文 B，所以 `C→D`，結果是 `BBD`。解密 `BBD` 應還原 `ABC`。這個例子比長句更容易看出 seed 與明文延長的交界。若輸入包含 `A-B`，連字號保持、也不會插入 key 流；你可用輸出與手算對照確認。

Autokey 的種子不必和訊息一樣長，但短 seed 並不表示更安全。它只提供 key 流的開端，後面受明文本身約束。若做作業或交換練習，除了記錄 seed 外，還應記錄版本是 plaintext-autokey、字母表採 A=0、以及非字母是否跳過；缺少其中一項都可能讓他人無法重現。

## 破解思路與限制

Autokey 消除了明顯的短週期重複，因此直接把密文按固定欄位拆開的維吉尼亞攻擊不一定有效。但它不是現代安全方案。攻擊者若猜到某段開頭明文，例如常見標題、問候語或檔案格式，就能從 `K=C-P mod 26` 推出初始 key 流；在種子後面，key 流又等於前段明文，猜測會形成可檢驗的鏈。語言的冗餘、詞典猜測與統計技巧可逐步擴大已知區域。

明文回饋也造成傳輸脆弱性。密文某一字元受損時，該位置先解錯；這個錯誤明文後來又成為 key 的一部分，所以在固定延遲後會再影響另一位置。攻擊者可利用可預測格式驗證猜測，收件者則難以僅靠後半段修復同步。真正的通訊加密需要明確處理錯誤、完整性與主動竄改，而 Autokey 沒有認證機制。

不要把「不重複短 key」宣傳為不可破解。它只減少了一種週期特徵，沒有提供足夠的密鑰熵、隨機性、認證標籤或安全證明。密碼、個資、Token 和商業文件不應使用它；現代需求應使用成熟函式庫和經審查的認證加密協定。Autokey 的合適用途是理解 key 流、回饋與密碼分析間的關係。

## 常見錯誤與自我檢查

最常見錯誤是把密文接到 key 後面，卻宣稱是本頁的明文 Autokey；第二是將 seed 無限重複；第三是在解密時試圖從右向左。請以 `B`／`ABC` 的 `BBD` 範例檢查實作，再把結果解密回原文。也請測試含空白的 `A A`：第二個 A 的 key 應是第一個明文 A，而不是空格。掌握這些邊界後，便能精確區分 Autokey 與普通維吉尼亞。

## 進一步比較與練習

可把 Autokey 想成一個非常簡單的「回饋」系統。一般維吉尼亞的 key 流完全由外部 key 決定，所以它是固定週期；明文 Autokey 在通過種子長度後，改由先前資料決定下一個偏移。這確實讓密文不再顯示短週期，但也把語言本身的規律帶進 key 流。自然語言不是隨機序列，常見單字、詞尾與句法仍能供分析者利用。密碼設計中「看起來不重複」和「可證明地不可預測」是不同層次的要求。

再試一個種子長度為二的例子。以 `BC` 加密 `AAAAA`：前兩格使用 B、C，得到 B、C；第三格使用第一個明文 A，得到 A；第四格仍使用第二個明文 A，得到 A；後面同理。因此密文是 `BCAAA`。若有人把 key 循環，會得到 `BCBCA`，兩種結果明顯不同。這個測試能快速確定程式是真的在接上明文，而不是只是另一個名稱的維吉尼亞。

解密除錯時，請把每一格的「目前已還原明文」寫在旁邊。前 `s` 格只能使用 seed；第 `s+1` 格開始，使用第一格已還原文字。若你的答案在剛跨過 seed 邊界後出錯，通常是索引少一格或多一格；若很後面才出錯，請檢查某個非字母是否錯誤地消耗了 key。這些系統化檢查比反覆猜 key 更有效，也有助於理解程式為何需要逐字走訪。

Autokey 與一次一密都會出現「key 流不重複」的表面特徵，但安全性完全不同。一次一密要求與訊息等長、真正隨機、從不重用且絕對保密的 key；Autokey 的後半段來自有高度結構的明文，並不滿足這些條件。兩者不能因為都不循環就畫上等號。

最後，若要把這個方法用於競賽或解謎，請先確認出題者是否指定明文 Autokey 或密文 Autokey，並確認是否把 J/I、空格或標點納入字母流。CipherTool 僅提供本頁規則，清楚標示這些限制可避免把工具答案誤判為錯誤。
