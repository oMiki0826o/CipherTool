# 維吉尼亞密碼（Vigenère Cipher）

> 分類：重複關鍵字的多表替換密碼。CipherTool 參數：非空白、只含英文字母的 `key`。

## 歷史背景與它想解決的問題

維吉尼亞密碼常被描述為古典密碼的重要里程碑。它的思想在文藝復興時期逐步形成，名稱通常與 Blaise de Vigenère 關聯；歷史上也有其他作者使用過多字母表的概念，所以不能把所有細節都簡化成單一發明者。它真正的新意是放棄「一個字母永遠換成同一個符號」的規則。相同的明文字母在不同位置可以因為關鍵字的不同字母而產生不同密文，因而打散單表替換最明顯的頻率特徵。

想像有二十六列凱薩位移表：第一列不位移，第二列位移一格，直到第二十六列位移二十五格。關鍵字的每一個字母告訴你這一位置要使用哪一列。關鍵字 `LEMON` 的 `L` 代表位移十一，`E` 代表四；寫完後又從 `L` 重複。這讓密碼看似比凱薩複雜得多，也曾因而被稱作難以破解的密碼，但那只是當時的評價。只要關鍵字重複，統計規律仍會以週期方式留下痕跡。

## 核心公式與關鍵字流

令明文字母索引為 `Pᵢ`、關鍵字第 `i` 個對應字母的索引為 `Kᵢ`，均使用 `A=0` 到 `Z=25`。加密與解密分別是：

```text
Cᵢ = (Pᵢ + Kᵢ) mod 26
Pᵢ = (Cᵢ - Kᵢ) mod 26
```

若關鍵字長度為 `r`，則實際使用的偏移為 `K[i mod r]`。因此它是多表替換：同一個 `E` 在關鍵字對應 `A` 時不動、對應 `B` 時變成 `F`、對應 `L` 時變成 `P`。關鍵字本身不是附在密文裡的文字，而是一串控制位移的數值；把它重複排在明文下方，只是方便手算的記法。

CipherTool 對英文字母套用關鍵字，並且只有遇到 ASCII 英文字母時才前進到下一個關鍵字位置。空白、數字、標點、中文或 emoji 會原樣保留，也**不會**消耗關鍵字。這個規則很容易被忽略：`A A` 用 key `BC` 時，第一個 `A` 用 `B`，空格跳過，第二個 `A` 用 `C`；不是用 `B`。不同教材可能選擇讓標點也消耗位置，兩種規則都能定義，但加解密雙方必須一致。CipherTool 的規則以目前實作為準。

## 手算範例

經典例子使用明文 `ATTACKATDAWN` 與 key `LEMON`。把 key 重複排列：

```text
明文：A T T A C K A T D A W N
關鍵：L E M O N L E M O N L E
位移：11 4 12 14 13 11 4 12 14 13 11 4
密文：L X F O P V E F R N H R
```

第一格 `A=0` 加上 `L=11` 得 `L`；第二格 `T=19` 加 `E=4` 得 23，也就是 `X`；第三格 `T=19` 加 `M=12` 得 31，取模二十六為 5，即 `F`。解密時以同一 key 反向減去偏移，`L-11=A`、`X-4=T`，即可回到原文。這個例子也顯示關鍵字的重複：第六個位置又使用 `L`。

若輸入是 `Attack at dawn!`，CipherTool 會保留原始大小寫、空白與驚嘆號，並讓 key 只跨過英文字母。手算前應先寫清楚你採用的大小寫與非字母規則；否則即使數學公式正確，結果也可能和工具不同。常見錯誤包括把 key 字母本身當作一開始就加一的位移、在 key 用完後停止加密、或在解密時仍使用加法。請記住 `A` 必須表示零位移，這也是為何索引常從零起算。

## CipherTool 操作

在 GUI 選擇 Classical Cipher → Vigenère Cipher，輸入文字與 key，再選 encrypt 或 decrypt。key 必須至少一個字元，且必須全是 ASCII 英文字母；`LEMON`、`lemon` 都可，程式會以字母位置處理。空字串、含空白的 `MY KEY`、含數字的 `KEY2`、含中文的 `密鑰` 都會被拒絕，因為目前實作沒有為它們定義一致的二十六字母偏移。

隨機參數功能會產生八個大寫英文字母的 key，適合作為練習的起點。但隨機外觀不等於現代安全：這個 key 仍被循環使用，且演算法的統計弱點沒有消失。若你要重現別人的答案，務必記錄完整 key、文字大小寫，以及文字中是否含非字母；單寫「用維吉尼亞」不足以重現結果。

## 破解方法：先找週期，再做頻率分析

維吉尼亞的關鍵弱點是 key 週期重複。Kasiski examination 會尋找密文中重複片段的距離，這些距離的公因數可能揭露 key 長度；Friedman test 與重合指數則透過字母重複率估計週期。一旦猜到長度，例如五，就把密文每五個位置拆成五欄。每一欄其實是一個普通凱薩密碼，因為該欄永遠用了同一個關鍵字偏移；對各欄做頻率分析即可逐步還原 key。

短密文、罕見語言或很長的 key 會讓分析較難，但「較難」不是安全保證。已知一段明文也很危險：將明文與密文逐字相減即可得到對應的 key 流，重複模式往往立刻露出 key。若 key 與訊息同長、真正隨機、且永不重用，形式上會接近一次一密（one-time pad）；但那已不再是重複 key 的維吉尼亞，並且需要非常嚴格的隨機性與金鑰配送管理。

## 安全限制與學習重點

維吉尼亞比凱薩和 Atbash 更能說明「改變映射」如何削弱單純頻率分析，但它沒有提供現代意義的安全。它不防止暴力與統計分析，不提供驗證或完整性，也不處理真實系統所需的隨機 nonce、認證標籤、金鑰交換與抗側信道問題。用更長但可猜的英文單字作 key，也常會被字典攻擊或已知格式破解。

它最適合用來練習模運算序列、週期、索引同步和密碼分析。使用 CipherTool 時，先以 `ATTACKATDAWN`／`LEMON` 檢查是否得到 `LXFOPVEFRNHR`，再自己加入空格與小寫，觀察 key 索引如何跳過非字母。真正需要保護的資料必須使用成熟、經過審查的現代加密方案；不要把維吉尼亞、Base64、ROT13 或多次位移拼在一起，誤以為層數增加就等於安全。

## 自我檢查

請以 key `B` 加密 `ABC xyz`，結果應是 `BCD yza`；因為 `B` 表示每個英文字母位移一格。再以 key `BC` 加密 `A A`，依 CipherTool 規則應得到 `B C`，空格不消耗 key。兩個小測試同時驗證零起算、循環與非字母處理。

## 常見誤解與實作細節

維吉尼亞表常被畫成二十六乘二十六的方格，但表格不是演算法本身。讀表時，在明文字母那一列與關鍵字字母那一欄交會處取密文；用公式則只需一次加法和取模，兩者結果完全相同。解密表看似需要反向搜尋，其實直接做減法更可靠。理解這個等價關係，能避免把行列方向記錯，也能看出多表替換其實是按位置選擇不同凱薩位移。

「關鍵字越長越安全」只在有限而且有條件的意義下成立。長度若接近密文長度，週期分析需要更多資料；但如果 key 是常見詞、歌詞、使用者名稱或可預測模式，字典攻擊和已知明文仍然很有效。更重要的是，重複使用同一 key 加密多封訊息會讓攻擊者累積統計資料，甚至可把兩段密文相減以消去 key 流的一部分。現代加密避免這些問題的方式不只是「把 key 寫長」，而是使用標準演算法、隨機或唯一的參數，以及正確的金鑰生命週期。

在程式設計上，關鍵字索引必須只在處理英文字母後遞增。若先遞增再檢查字元，或在標點處也遞增，解密端若沒有完全採同一做法就會從該位置起全部錯位。這種同步失敗是流式密碼與實際通訊協定也會遇到的概念，只是維吉尼亞把它以很容易觀察的形式呈現。CipherTool 對加密與解密共用同一套字元走訪規則，正是為了確保它們能互為反向操作。

可再做一個除錯練習：以 `KEY` 加密 `A-BC`。第一個 `A` 用 K，連字號保留且不前進，`B` 用 E，`C` 用 Y。把每個位置的 key 索引寫在紙上，便能很快找出與工具輸出不一致的原因。這比只背經典範例更能掌握真實輸入中標點、大小寫與格式的影響。
