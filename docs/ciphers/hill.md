# 希爾密碼（Hill Cipher，2×2）

> 分類：矩陣式多字母替換。CipherTool 僅支援 2×2 整數矩陣，參數格式為四個逗號分隔整數，例如 `3,3,2,5`。

## 歷史與矩陣觀念

希爾密碼由 Lester S. Hill 在 1929 年提出，是早期把線性代數明確引入密碼設計的代表。它不再逐字處理，而是將多個字母視為向量，透過矩陣乘法一次得到多個密文字母。這會混合相鄰字母的資訊：單一明文字母不再有固定的單一替換，因而比單表替換更難以用單字母頻率直接分析。

CipherTool 使用最容易手算的二乘二版本。將 A=0 到 Z=25，明文每兩字母組成欄向量，key 矩陣 `K=[[a,b],[c,d]]`。加密為 `C=K×P mod 26`；解密使用 `K⁻¹ mod 26`。要能解密，行列式 `det(K)=ad-bc` 必須與 26 互質，否則矩陣在模二十六下沒有反矩陣，資訊會碰撞而無法唯一還原。

## 範例、工具行為與限制

以矩陣 `[[3,3],[2,5]]` 加密 `HI`：H=7、I=8，計算第一項 `3×7+3×8=45 mod 26=19(T)`，第二項 `2×7+5×8=54 mod 26=2(C)`，得到 `TC`。解密時使用模反矩陣即可回到 HI。CipherTool 只保留英文字母、轉大寫；J 不合併；若明文長度為奇數，會補 X。解密也以二字母組處理，因此不會自動移除末尾 X。

矩陣參數必須剛好四個整數，且行列式與 26 互質。像 `2,4,2,4` 的行列式為零，工具應拒絕。這是數學必要條件，不是任意限制。輸入的空白、標點、中文會被略過，故 `A-B` 與 `AB` 產生相同處理字母；此工具不適合需要保留格式的資料。

## 破解與學習價值

若攻擊者取得足夠的明文／密文對，可將多組向量排列後解線性方程，求出 key 矩陣。自然語言也保留 digraph 統計特徵，短矩陣和已知格式都削弱安全性。希爾密碼沒有隨機性、認證或完整性，因此不能保護真實敏感資料。它的價值是練習模矩陣、行列式、反矩陣與分組轉換。

## 自我檢查

以 `3,3,2,5` 加密 HI 應得 TC，再解密應回到 HI。以奇數長度 `CAT` 加密時會加入 X；以不可逆矩陣操作時應報錯。這些測試分別驗證矩陣乘法、填充與可逆性。

## 從字母對到向量

要手算希爾密碼，先把兩個字母排成直欄而非橫列。以 `AB` 為例，A=0、B=1，向量是 `[0,1]ᵀ`。若矩陣為 `[[3,3],[2,5]]`，相乘後第一個分量是 `3×0+3×1=3`，第二個是 `2×0+5×1=5`，輸出 D、F。換成 `[1,0]ᵀ` 則輸出 C、D；這直接展示兩個輸出都可能同時受到兩個輸入影響。採行向量或列向量都可定義，但矩陣乘法方向必須和 key 約定一致；CipherTool 採前述欄向量慣例。

二乘二反矩陣的公式是：若 `K=[[a,b],[c,d]]`，行列式 `Δ=ad-bc`，則 `K⁻¹=Δ⁻¹[[d,-b],[-c,a]] mod 26`。其中 `Δ⁻¹` 是 Δ 在模二十六下的反元素。這一步將普通線性代數和模運算結合起來：負數可先保留，最後取模化為 0 到 25；但若 Δ 與 26 有公因數，就找不到反元素，整個解密矩陣不存在。程式驗證的正是這個條件。

例如 key `3,3,2,5` 的行列式是 `15-6=9`，而 9 的反元素是 3，因為 `9×3=27≡1 mod 26`。因此它可逆。若 key 是 `2,4,2,4`，行列式為零；若行列式是偶數或十三的倍數，也同樣不可逆。選一個看似「數字夠亂」的矩陣不等於可用 key，這是希爾密碼最重要的參數規則。

## 填充、格式與可逆性的代價

分組算法必須讓字母數為偶數。CipherTool 會將 `CAT` 正規化為 `CAT` 後補 X，實際加密四個字母；解密會回傳含 X 的字串。程式不自動刪 X，因為 `X` 可能本來就是訊息最後一字母，任何自動猜測都可能破壞資料。這與 Playfair 的插入 X 有相似的歧義，但原因不同：Hill 是群組長度，Playfair 是避免同一 pair。

非字母被略過也代表輸出不是格式保留型轉換。`A-B`、`AB`、`A B` 都只留下 AB 進入矩陣，因此會得到相同密文；原始標點、空白和大小寫不可從結果恢復。這是古典手算常見的正規化，但對真實文字或任何結構化資料都不合格。使用工具前必須確認你想保護的是字母序列，還是需要逐位元無損還原的完整資料。

## 破譯為何仍可行

希爾密碼把頻率從單字母擴展至二字母，確實比凱薩更難手工猜測；但它是線性的。若攻擊者知道兩組線性獨立的明文向量與其密文向量，可在模二十六下解出 K，或將多組資料組成矩陣關係 `C=KP`。實務密文也常含可猜的格式、固定開頭和冗餘語言，提供已知明文。更大的矩陣會增加手算負擔，不會自動得到現代安全。

此外，所有加密區塊獨立處理；相同明文 pair 在相同 key 下永遠得到相同密文 pair。攻擊者可利用重複、分組邊界與 digraph 統計。沒有隨機 nonce、認證標籤或安全金鑰交換的古典矩陣轉換，不能抵抗主動竄改或現代計算分析。它應被視為代數教材和歷史算法，而不是安全函式庫。

## 進階練習

先自己求出 `3,3,2,5` 的反矩陣，再用它解 `TC`，確認回到 HI。接著將矩陣改為一個行列式為偶數的例子，說明為何兩個不同向量會壓到同一輸出。最後比較 `CAT` 和 `CATX` 的處理：它們都可能導向同樣的正規化結果，正是填充歧義的具體證據。這些練習比單純背公式更能掌握矩陣可逆、資料正規化與密碼限制之間的關係。

矩陣元素可大於二十五或為負數，因為每次運算最後都取模二十六；然而在寫作業與分享 key 時，將元素化簡到 0–25 最易檢查。也要明確寫出四個值是按列還是按行輸入：CipherTool 的 `3,3,2,5` 表示第一列 3、3，第二列 2、5。少了這個排列約定，即使所有數值相同也可能得到不同答案。

希爾密碼也能用來理解線性變換的「擴散」直覺：改變一個輸入分量，通常會讓同組兩個輸出都改變；這比凱薩逐字獨立更能混合局部資訊。不過二乘二矩陣只在每個 pair 內擴散，跨 pair 完全獨立，攻擊者仍能利用區塊邊界。現代分組密碼需要遠更複雜、多輪且有安全分析的結構。

手算反矩陣時，建議每一步保留未取模的中間值，再在最後化簡，能減少負數錯誤。驗證反矩陣最直接的方法是計算 `K×K⁻¹ mod 26` 是否為單位矩陣；若不是，就不應繼續解密。這比只檢查某個單字範例可靠。

矩陣 key 若以明文方式分享，任何人都可解密；若僅把四個數字藏在程式中，也只是隱藏實作而非安全設計。希爾密碼的歷史價值在於提供線性代數模型，讓人能精確分析其可逆性與已知明文弱點。它不該被誤用為「有矩陣就很安全」的範例。

二乘二版本尤其適合手算，但也意味每次只混合兩個字母。擴大矩陣維度會增加運算與 key 空間，同時提高同步和反矩陣計算負擔；不論維度多大，缺乏現代設計與隨機化仍不適合真實保密。

輸入矩陣前可先算行列式，再用 `gcd(det,26)` 檢查是否為一；這比先加密、遇到錯誤再猜原因有效。把這個檢查列為手算的第一步，也能避免在不可逆 key 上浪費時間。

矩陣格式中的逗號只是 GUI 參數分隔符，不是數學的一部分；輸入前後多餘空白可以避免，但四個值的順序不可改。先用已知向量驗算一組輸出，是交換矩陣 key 前最可靠的同步方式。
