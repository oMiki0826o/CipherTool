# 豬圈密碼（Pigpen Cipher）

> 分類：圖形符號替換密碼。CipherTool 使用可複製的 Unicode token，輸入只支援英文字母與空白。

## 名稱、背景與圖形概念

豬圈密碼又常被稱為共濟會密碼（Freemason's cipher）或格欄密碼。它不是把 A 換成另一個英文字母，而是把每個字母換成「所在格子的外框形狀」。名稱來自圖案看起來像簡化的圍欄或豬圈：把九個字母放進井字形的九格，把另外九個字母放進相同格子但加上一個點，再以兩個叉形的四區容納剩餘字母，最後一組同樣加點區分。

它在十八、十九世紀的社團、遊戲、少年活動和私密留言中很常見，也經常出現在尋寶、密室與解謎題。圖形外觀讓初見者覺得神祕，卻不代表有強安全性；只要知道格子排列或找到一張對照圖，就能直接閱讀。它本質上仍是固定的一對一替換：A 每次都會變成同一個角落圖形，E 每次都會變成同一個中心圖形。

紙筆版最重要的是畫出格子，而不是畫出字母本身。加密者將字母所在格的邊界抄下來，並依需要加點；解密者看符號的方向、邊界與點，反查它屬於哪一個格。各種資料來源可能採不同字母排列、不同點的位置，甚至會把 I/J 合併，因此交換訊息前必須同意同一份圖表。本頁以 CipherTool 的固定 A 到 Z 對照為唯一規則。

## CipherTool 的文字化符號表

真正手繪豬圈的線段能呈現完整格子，但純文字介面無法保證每個裝置字型一致。CipherTool 因此用穩定可複製的 Unicode box-drawing token 代表圖形位置，並以 `•` 表示點。A 到 I 依序對應未加點的九格：

```text
A ┌   B ┬   C ┐   D ├   E ┼   F ┤   G └   H ┴   I ┘
```

J 到 R 使用同一位置加點，例如 `J=┌•`、`N=┼•`、`R=┘•`。最後八個字母使用叉形位置：`S=⌜`、`T=⌝`、`U=⌟`、`V=⌞`，再以 `W=⌜•`、`X=⌝•`、`Y=⌟•`、`Z=⌞•` 表示加點版本。這一表是程式定義，並非唯一的歷史標準；優點是輸出可貼到文字檔、聊天或 GitHub，不必傳送圖片。

每個 token 以空白分隔，單字間以獨立 token `/` 表示。例如 `CAT` 的輸出是 `┐ ┌ ⌝`，因為 C 是 `┐`、A 是 `┌`、T 是 `⌝`。`CAT DOG` 則會包含 `/` 作為空白標記。這個分隔規則很關鍵：若把 `┌•` 拆成 `┌` 與 `•`，解碼器會把它視為錯誤輸入；若把所有 token 黏在一起，程式也無法可靠判定邊界。

## 加密與解密流程

加密時，CipherTool 先將英文字母轉為大寫，再逐字查 token 表。空白與其他空白字元輸出成 `/`，每個結果 token 以一個空白隔開。大小寫在此密碼中不保留，因為圖形表只定義二十六個字母；`hello` 與 `HELLO` 都會得到相同符號流。非字母且非空白的內容，例如數字、逗號、連字號、中文、emoji，會直接造成錯誤，而不是悄悄原樣混進密文。這能避免解密時不清楚某個字符究竟是格式還是 token。

解密時，程式以空白切分輸入，看到 `/` 就輸出一個空格，看到定義中的 token 就輸出對應大寫字母。輸出會是大寫英文，因為原始大小寫在編碼時沒有保留。多個輸入空白在切分後不表示多個詞間空格；真正要表示每個空白都必須寫一個獨立 `/`。這是文字化表示的設計取捨，和手繪版本看見字距的方式不同。

手算時可先畫兩個井字與兩個叉字。第一個井字填 A-I，第二個填 J-R 並規定全部加點；第一個叉填 S-V，第二個叉填 W-Z 並加點。遇到字母時只畫格子方向，不畫其內部字母。解密時反向辨識。最常見錯誤是忘記點、把角落方向旋轉，或把 I/J 合併的舊圖表套到這個完整二十六字母版本。使用工具時，應以本頁 token 對照而非搜尋到的任意圖片為準。

## 在 CipherTool 中操作

選擇 Classical Cipher → Pigpen Cipher。選 encode 時輸入英文與空白；選 decode 時貼上以空白分隔的 Unicode token。介面不需要 key，因為對照表固定且公開。若字型讓符號顯示不清楚，可複製輸出到支援 Unicode 的編輯器，或直接參考本頁對照表；不要自行把 token 換成相似的全形符號或圖片文字，解碼必須完全匹配。

試用範例：輸入 `DOG`，預期得到 `├ ⌝ └`。把這三個 token 貼回解碼欄位，應得到 `DOG`。再輸入 `A B`，結果為 `┌ / ┬`，可檢查 `/` 的空白規則。若輸入 `A-B` 報錯，這是符合設計的結果；可先把連字號改成空白，或改用能保留標點的其他古典密碼。

## 破解與安全性限制

豬圈密碼沒有秘密 key，破解通常只需辨識圖形。攻擊者可從井字、叉形和點的結構猜出方法，再套用常見對照表；即使排列有些變體，頻率、重複符號與單字長度仍能協助還原。圖形不是隨機符號，方向和加點的規律本身已暴露大量結構。若訊息很短，字謎上下文、題目主題和常見字也常足以猜出。

將符號轉成 Unicode、圖片、手寫或不同字型，不會改變密碼學強度；那只是改變表示媒介。固定映射仍然保留同樣的統計特徵，也沒有驗證訊息真偽的功能。它不該用於密碼、個資、秘密計畫或任何敏感內容。合適的用途是歷史展示、兒童活動、解謎和理解「符號替換」與「資料編碼」的差異。

從學習角度，豬圈很適合比較視覺密碼與一般字母替換。它讓人看見，密文不像英文字母並不代表更難破解；真正影響安全的是未知 key、足夠的熵、抵抗已知攻擊的設計與正確使用方式。若需要真實保密，請使用經過審查的現代加密系統，而不是自行調整格子、加上裝飾或把多個圖形密碼串接。

## 自我檢查

請編碼 `CAT`，結果應為 `┐ ┌ ⌝`；解碼相同 token 應得到 `CAT`。再編碼 `A B`，確認中間是 `/`。最後試輸入 `A1`，工具應拒絕而非忽略數字。三個測試分別驗證對照表、空白邊界與輸入範圍。

## 圖形密碼的閱讀技巧

第一次看手繪豬圈時，建議不要急著逐個猜字母，而是先把符號按「井字／叉字」和「有點／無點」分四組。這四組各自對應連續的字母區段，方向再決定區段內的位置。比如看到 `┬•`，先知道它是加點井字組，再看它位於上中格，就能定位到該組第二個字母 K。這種分層辨識比死背二十六個符號更快，也能幫助你發現某個符號少了點或方向畫反。

歷史圖表中常把兩個同形符號用點、陰影或小圈區分；電腦文字只用一個 `•` 是為了可攜性。複製時請保留 token 內的點與 token 間的空白，並避免輸入法把半形空白替換成看似相同的特殊空白。解碼器以一般空白切分，大多數正常空白、換行和 tab 都可作為分隔，但符號本身必須精確。若在某些字型中 `⌜`、`⌝` 難辨，請以程式碼字元複製，而不是依外觀重新輸入。

豬圈也能用來討論可用性與安全性的拉鋸。圖形表對熟悉者很快，對陌生人有初見障礙，這常被誤認為安全；然而障礙只是「不知道規則」而非難以計算。只要規則被公開或猜中，所有訊息立即可讀。現代密碼學假設規則會公開，因此必須把保護建立在秘密 key 和嚴謹演算法上。

若將本工具輸出貼到題目或文件，最好同時提供「CipherTool Pigpen token 格式」的註記。這能避免讀者拿傳統 I/J 合併圖表解不出 `J`，也避免把 `/` 誤當除號。清楚的格式契約是可重現教材的一部分。
