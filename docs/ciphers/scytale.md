# 密碼棒（Scytale）

> 分類：器具式置換密碼的軟體模擬。CipherTool 參數：`columns`，必須是至少 2 的整數。

## 歷史上的棒子，程式中的欄數

Scytale（常譯密碼棒）通常和古希臘斯巴達的軍事通訊故事連在一起。傳說中，發信者把狹長皮條螺旋纏在固定粗細的圓棒上，沿棒身寫下訊息；拆下皮條後，字母順序看起來混亂，只有纏回相同粗細的棒子才會在相鄰位置重新排成可讀文字。歷史細節與實際使用方式仍有學術討論，但它是很好的器具式置換概念：秘密不是另一套字母，而是讓文字在正確幾何排列下才能重組的尺寸。

電腦不需要真的有一根棒子，也能模擬它的關鍵條件。CipherTool 將「棒徑／每圈容納的格數」抽象成 `columns`：把明文由左到右寫成每列固定欄數的虛擬表格，再按欄由左到右讀出。這相當於把皮條纏繞後在一種方向寫入、拆開後沿另一方向閱讀。工具沒有要求實體棒子；columns 就是雙方必須共享的器具尺寸資訊。

這個抽象也揭示了歷史器具的限制。真正皮條的寬度、棒徑、字距和每圈對齊都可能影響可讀性；軟體版本則把所有字元視為等寬格子，明確規定只由欄數決定排列。因此 CipherTool 是可重現的教學模擬，不是對古代材料與書寫方式的物理復原。

## 排列規則與公式

若 columns 為 `c`，明文位置 `i` 在虛擬表格中的列為 `floor(i/c)`、欄為 `i mod c`。加密結果不是逐列讀，而是固定一欄後跳 `c` 個字元：先讀原文索引 `0,c,2c,…`，再讀 `1,1+c,1+2c,…`，直到最後一欄。程式概念可寫成：

```text
ciphertext = text[0::c] + text[1::c] + ... + text[c-1::c]
```

以 `WEAREDISCOVERED` 和 columns 4 為例，先逐列寫成：

```text
W E A R
E D I S
C O V E
R E D
```

依欄讀出：第一欄 `WECR`、第二欄 `EDOE`、第三欄 `AIVD`、第四欄 `RSE`，密文為 `WECREDOEAIVDRSE`。最後一列不需要補位，第四欄只是比前面短。這是 CipherTool 的實際規則；有些歷史或題目版本可能以列數、棒周長或填充符號表示尺寸，不能直接假定結果相同。

## 解密為什麼要先計算欄長

解密者收到的是欄串接的密文。若文字長度為 n、欄數為 c，先計算 `base, extra = divmod(n,c)`；原表前 extra 欄各有 `base+1` 個字元，其餘欄各有 `base` 個字元。原因是加密前由左到右逐列填入，最後一列只會填到左側幾欄。將密文依這些長度切成欄段後，再由第一列到最後一列、每次從各欄取一字元，就可還原明文。

上例 n 為 15、c 為 4，所以前三欄長 4、最後一欄長 3。將 `WECREDOEAIVDRSE` 切成 `WECR | EDOE | AIVD | RSE`，逐列交錯讀便得到 `WEAREDISCOVERED`。常見錯誤是把每一欄硬切成相同長度，這會在最後一列不完整時造成字元位移；另一錯誤是把 columns 當成列數，恰好是矩陣轉置方向顛倒。

## CipherTool 操作與字元範圍

在 GUI 選 Classical Cipher → Scytale，輸入文字、設定 columns，再選 encrypt 或 decrypt。columns 至少為二；一欄不會改變順序，不構成有效的器具排列。程式保留所有字元，包含英文字母、中文、空白、換行、數字與標點，並把它們都算入格子。這使操作能完全可逆，但也表示改掉一個空白、換行或全形字元都可能改變後面排列。

可先以 `WEAREDISCOVERED`／4 重現上例，再以包含空白的 `A B C` 實驗。不要在一端先刪除空白、另一端保留；雙方必須使用逐字相同的原始文字與 columns。若人類使用實體皮條，字距和棒徑也扮演相同的同步角色；程式只是將它們明確簡化成固定欄數。

## 破解與安全限制

密碼棒只提供一個小整數 key。攻擊者通常嘗試合理欄數，對每個候選解密並尋找自然語言、已知詞或格式，成本極低。字母頻率不變、文字長度不變，空格若保留還會提供更多線索。知道原文可能的開頭或結尾時，甚至能很快排除錯誤欄數。

它不會保護資料免於竄改：攻擊者替換密文一字元，收件者只會在某個位置看到不同字元，沒有驗證訊號。也沒有安全的 key 交換、隨機化或防重放能力。它適合歷史教學、幾何化思考與置換演算法練習，不適合任何敏感資料。若真實需求是保密與完整性，應使用經過審查的現代認證加密。

## 自我檢查

用 columns 4 加密 `WEAREDISCOVERED`，應得 `WECREDOEAIVDRSE`；以同一欄數解密必須逐字回復。再測試文字長度不能整除欄數的情況，例如 `ABCDE`／3，確認最後一列不補 X、解密仍可回復。最後試 columns 1，工具應拒絕。三項檢查分別涵蓋排列、非整齊表格與參數邊界。

## 與縱欄式移項的差別

Scytale 與縱欄式移項都會畫出表格，因此很容易混淆。密碼棒只有一個數值尺寸，欄由左到右固定讀取；縱欄式移項另外以 keyword 排列欄的讀取順序。若 columns 為四，Scytale 永遠讀第一、第二、第三、第四欄；縱欄則可能依 A、B、E、R、Z 的排序讀第五、第三、第二、第四、第一欄。兩者都不改變字元本身，但 key 模型、手算程序和解密欄長分配不同。

密碼棒的尺寸也可用「每圈字數」或「表格寬度」表達，教材必須先確認採哪個定義。有些來源以棒長方向的列數作 key，結果是同一矩陣採相反方向讀取；這在數學上可轉化，但直接比較密文會不同。CipherTool 對外公開的規則是 columns，因此遇到「直徑」或「圈數」等歷史描述時，應先畫一個短例子校正，不應直接填猜測值。

## 物理器具帶來的實務問題

皮條必須在同粗細的棒上以相同緊度和對齊方式纏繞；若每圈偏移、字距不一或起點不同，即使棒徑相同也難以讀出訊息。這正是物理密碼與程式模型的差異。程式將每個 Unicode 字元抽象為一格，沒有字寬、紙條邊緣、纏繞斜率或可視方向等問題，因此結果可精準重現，但也失去那些歷史上的操作限制。

可把這個差異當成設計問題思考：一套加密規則若依賴未寫下的物理細節，收件者可能無法成功解密；若把每個細節寫清楚，攻擊者也同樣能照做。真正安全不是靠模糊規格，而是即使規格公開，仍需沒有 key 的人無法計算出明文。Scytale 的 columns 太小，顯然不符合這個要求。

## 解題與錯誤診斷

若用錯 columns，解密結果通常不是完全亂碼，而會出現零星像單字的片段；這種巧合不能證明 key 正確。應檢查整段語法、重複片段、原文長度與重新加密是否能回到原密文。當文字長度較短時，多個欄數甚至可能給出可讀候選，題目上下文或已知格式才是額外判據。

程式測試除了正常範例，也應包含空字串、columns 大於字串長度、含換行與 Unicode 字元。因為實作以 Python 字串切片交錯處理，這些字元都佔一個位置；使用者若在另一端把文字轉碼、正規化或移除換行，結果便不再相同。這是可逆字元置換的基本前提。

同一段訊息若 columns 從四改為五，密文會完全改變，但其實沒有引入新的字母規則；這正說明 key 的作用是排列位置。把兩個結果都畫成表格，比直接比較密文字串更容易看出差異。
