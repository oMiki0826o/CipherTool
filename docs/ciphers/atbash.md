# 阿特巴希密碼（Atbash Cipher）

> 分類：固定、對稱的單表替換密碼。CipherTool 不需要輸入密鑰，加密與解密使用同一規則。

## 名稱與歷史脈絡

阿特巴希（Atbash）是最早有文字記錄的替換密碼概念之一，名稱來自希伯來字母的第一個字母 Aleph、最後一個字母 Tav、第二個字母 Beth 與倒數第二個字母 Shin 的組合。它的核心想法非常直觀：把字母表首尾對折，第一個字母對最後一個、第二個對倒數第二個，依此類推。古代資料中的實際字母表、拼寫習慣與現代英文字母並不相同，但「反向字母表」這一規則已足以讓它成為理解替換密碼的好起點。

CipherTool 實作的是現代英文二十六字母版本：`A↔Z`、`B↔Y`、`C↔X`，直到 `M↔N`。它沒有可選密鑰，也沒有依位置改變的狀態；任何人只要知道使用 Atbash，就能立即讀回內容。因此它在歷史研究、文字謎題與程式練習之外，不提供任何實際機密性。把它視為「鏡像字母表轉換」比把它想成安全加密更精確。

## 核心原理與數學表示

若採用 `A=0`、`B=1` 到 `Z=25` 的索引，明文索引為 `P`，密文索引為 `C`，Atbash 可寫為：

```text
C = 25 - P
```

因為 `P` 本來就在 0 到 25 之間，所以不需要像凱薩密碼那樣處理位移繞回。把這個函數再做一次：`25 - (25 - P) = P`，因此它是自反的：加密和解密完全一致。若用模運算也可寫成 `C = -P - 1 mod 26`，但對初學者而言，直接用「索引和為二十五」更清楚。這種對稱性與 ROT13 相似，差別是 ROT13 將索引加十三，而 Atbash 將索引映射到鏡像位置。

字母表兩端配對可以寫成：

```text
明文：ABCDEFGHIJKLMNOPQRSTUVWXYZ
密文：ZYXWVUTSRQPONMLKJIHGFEDCBA
```

同一個明文字母每次都對應同一個密文字母，故它仍是單表替換。保留這種一對一映射雖使轉換可逆，卻也讓英文的頻率、雙字母組合、相同單字模式與空格位置保留下來。Atbash 甚至比帶密鑰的凱薩更弱，因為攻擊者不需嘗試二十六種位移，只需套用唯一的反轉表。

## 加密、解密與手算例子

以 `MEET AT DAWN` 為例，`M` 是第十三個（零起算為 12）字母，鏡像是 `N`；`E` 對 `V`；`T` 對 `G`。把每個英文字母替換後得到：

```text
明文：MEET AT DAWN
密文：NVVG ZG WZDM
```

空格沒有映射規則，所以原樣保留。現在把 `NVVG` 再查一次反向表：`N→M`、`V→E`、`V→E`、`G→T`，便回到 `MEET`。這個「同一動作做兩次」是最可靠的手算驗證方式。大小寫也應保留：`Hello` 會成為 `Svool`，而非全大寫的 `SVOOL`。數字、標點、換行和中文不在英文字母表內，CipherTool 同樣保持原樣。

常見錯誤是把字母「倒著寫」而不是逐字替換。倒著寫 `ABC` 會得到 `CBA`，Atbash 卻應得到 `ZYX`；前者改變的是位置順序，屬於置換，後者改變的是每個符號，屬於替換。另一個錯誤是認為 `A` 應對 `Y`，那會少跳過字母表尾端的 `Z`。建立完整的兩列對照表，或使用公式 `25-P`，可以避免這些偏一格的問題。

## 在 CipherTool 中使用

在 GUI 的 Classical Cipher 類別選擇 Atbash，輸入文字後執行。工具不要求位移量、關鍵字或替換字母表；若介面顯示加密與解密模式，兩者對 Atbash 都套用同一映射，輸出相同。它只處理 ASCII 的 `A-Z` 與 `a-z`，因此混合文字如 `CODE：中文 123` 會只改成 `XLWV：中文 123`。這個範圍要特別注意，因為「看起來沒有改變」可能是輸入不在支援字母表內，而非程式沒有執行。

練習時可先不用工具，寫出二十六字母的上下對照列，處理十個字元以內的英文單字；再把結果貼到 CipherTool 做雙向檢查。若輸出不同，請檢查是否把 `M` 和 `N` 的配對寫反，或無意間刪除了空格與標點。由於演算法不使用秘密，工具的價值在於快速、穩定地重現明確規則，不在於替使用者保管任何金鑰。

## 破解思路與現代安全限制

破解 Atbash 的成本幾乎為零。知道名稱的人直接套用一次即可；不知道名稱的人也能因為它是固定單表替換而用頻率分析、常見詞模式或已知明文找出映射。英文中密文最常見的符號會對應某個最常見的明文字母，短字的重複模式會揭露 `THE`、`AND` 等候選，而鏡像對稱的映射很快能被辨認。空格與標點未被隱藏，還額外幫助分詞。

不能把「不用密鑰」誤解為省去金鑰管理的安全設計。沒有秘密就沒有存取界線；任何看到資料的人都具備和預定收件者一樣的還原能力。把 Atbash 與 Hex、Base64 或其他公開編碼串起來，也只是讓人多做幾個可逆步驟。它不會抵抗截取、竄改、重放、暴力枚舉或已知明文攻擊，更不提供身分驗證與完整性保護。

它的學習價值在於清楚區分兩類概念：字母「值」的鏡像替換，以及字元「位置」的重新排列。理解這個差別後，閱讀豬圈、單表替換、柵欄或縱欄移項會更容易。實務上，敏感資料應使用具備隨機性、金鑰管理與完整性驗證的現代加密系統；Atbash 僅適合公開教材、解謎和低風險的文字遊戲。

## 自我檢查

請試算 `AZ BY MN`。正確結果是 `ZA YB NM`，再做一次必須完全回到原文。此例同時驗證首尾、第二與倒數第二、以及中間兩個字母的鏡像關係。若答案只把每個單字反轉，代表你做的是文字倒序，不是 Atbash。

## 與其他入門密碼比較

Atbash、凱薩與 ROT13 都是固定替換，因此它們的共同弱點比差異更重要。三者都不改變字元數量、空白、標點或相同字母的重複模式；密文中兩個相同字母，原文也必定是同一個字母。差別在於凱薩允許選擇位移量，ROT13 把位移固定為十三，Atbash 則以字母表鏡像作唯一規則。從攻擊者角度看，ROT13 和 Atbash 都沒有真正需要猜測的密鑰；凱薩雖有位移，也只有二十六種可能。

做題時可利用這些結構快速分類。若 `A` 的候選對應是 `Z`、`B` 對 `Y`，優先試 Atbash；若所有字母都朝同方向等距移動，優先試凱薩；若剛好相隔十三格且同一轉換可還原，便是 ROT13。這不是萬無一失的鑑識法，因為任意單表替換可能碰巧呈現某些配對，但它能讓你先用成本最低的假設驗證。只要一次完整轉換後出現自然語言，假設就很有力；若只有零星單字巧合，應繼續檢查其他方法。

Atbash 也能說明「演算法公開」並不是問題本身。現代加密同樣可以公開演算法，但它必須依賴巨大且不可猜測的密鑰、足夠的隨機性與嚴格的安全證明或分析。Atbash 沒有這些元素，所以不能因為規則看起來優雅、輸出看起來陌生就誤認為可靠。教育上把弱方法講清楚，反而有助於避免把字元替換誤用到真實資料。

若你要設計一道練習題，最好明示字母表、是否保留大小寫、非字母如何處理，以及答案是否應保留原始格式。這些規格決定了還原結果能否逐字相等。CipherTool 的選擇是保留大小寫與非字母，讓操作前後可直接比對；其他教材若先把所有內容正規化成大寫，也可能是合理約定，但不可混用兩種約定後再宣稱結果不一致。
