# 縱欄式移項密碼（Columnar Transposition）

> 分類：關鍵字控制的置換式密碼。CipherTool 參數：非空白、只含英文字母的 `key`。

## 原理與歷史位置

縱欄式移項將明文按列寬寫進表格，再依關鍵字字母的字母序決定讀取各欄的順序。它不改變字母本身，因此和柵欄密碼一樣保留完整字母頻率；不同點是排列規則由 key 決定，而非固定鋸齒路徑。歷史上的軍事、外交與商業通訊常採類似的表格轉置，因為紙筆容易操作，且可藉不同關鍵字產生不同排列。

假設 key 是 `ZEBRA`。把 key 寫在欄頂，按字母序排序時 A 最先、B 次之、E、R、Z 最後，因此讀欄順序是原來第 5、3、2、4、1 欄。加密者逐列填滿文字後按此順序抄下各欄；收件者知道 key，就能重建欄順序與原表。key 的意義不是直接把每個字母替換，而是定義一個欄位排列。

CipherTool 採不補位版本：最後一列可能不完整，程式不會添 X 或空格填滿。這比歷史資料中的某些版本簡單，也避免解密後無法判定哪些 X 是原文、哪些是填充。若比對外部範例，必須確認對方是否補位、先按行還是按列填入、以及同字母 key 的排序規則。

## 加密流程與重複 key 字母

以 key `ZEBRA`、明文 `WEAREDISCOVERED` 為例，表格寬度五：

```text
Z E B R A
W E A R E
D I S C O
V E R E D
```

按 A、B、E、R、Z 的欄順序讀取，分別得到 `EOD`、`ASR`、`EIE`、`RCE`、`WDV`，串接就是密文。實際訊息長度不一定剛好整除欄數，最後一列少掉的格子不會存在；解密時必須先依文字長度計算每一原始欄到底有幾個字元，再按排序後的欄次從密文分配回去。

key 若含重複字母，CipherTool 採穩定排序：先比較字母，再以原始欄索引決定相同字母的先後。例如 `BALLOON` 的兩個 L 保持左邊 L 先、右邊 L 後。這個細節必須寫清楚，因為有些手算教材會為重複字母任意編號，若雙方編號不一致，解密會失敗。key 必須是 ASCII 英文字母且非空，大小寫只影響外觀，不影響排序。

## 解密與工具操作

解密先計算原表的列數與各欄長度。若文字長度為 n、key 長度為 w，完整列數是 `n//w`，前 `n mod w` 個原始欄多一個字元，因為加密時是由左到右逐列填入。接著按照 key 的排序順序，將密文切成各欄應有的長度；最後按原欄順序逐列取字元，便回復明文。這個「先算欄長，再依排序填欄」是解密的核心。

在 GUI 選 Classical Cipher → Columnar Transposition，填入 key 後選 encrypt 或 decrypt。程式保留任何文字字元：中文、標點、數字、換行與空白都會參與表格位置，而不只處理英文字母；但 key 本身必須是英文字母。這使它能無損轉置任意文字，也代表不同的換行或多餘空白都會改變密文，重現時不可自行整理格式。

## 破解與安全限制

若 key 長度很短，可枚舉欄數及欄排列並以語言分數排序；已知明文片段或固定格式尤其容易幫助判定欄順序。字母頻率沒有被隱藏，攻擊者只需找出如何把密文重新交錯成合理語言。重複使用同一 key 加密多封訊息提供更多對齊線索，長度也可能洩露欄數的因子。

它不提供現代機密性、完整性、認證或抗竄改能力。將 key 取成很長的英文單字、混入大小寫或再做 Base64 都不會彌補設計限制。合適用途是歷史與演算法學習、解謎或理解穩定排序；敏感資料必須使用成熟的現代加密。

## 自我檢查與常見錯誤

請以 key `ZEBRA` 手畫短表，再比較工具輸出。重複字母 key 可用 `BALLOON` 測試，確認相同 L 的欄依原位置排序。常見錯誤包括解密時每欄硬切相同長度、忘記最後一列不補位、或把 key 當成逐字位移。若加解密無法精確回到含空白的原文，先檢查是否在其中一端刪掉了空白或換行。

## 延伸理解

縱欄式移項說明 key 不一定要作用在字母值，也能作用在索引順序。這種觀念在資料庫排序、矩陣轉置與通訊交錯中都會出現。安全性上，單一置換只改變局部結構，對統計攻擊仍很脆弱；但作為程式練習，它要求正確處理排序、重複項、非整齊矩陣和反向重建，十分適合驗證邊界條件。

## 延伸的表格推理

若 key 寬度為 w、文字長度為 n，最後一列的長度是 `n mod w`；當餘數為零時，每欄等長。非零時，因為填入方向從左到右，原始表左邊的前幾欄比右邊多一字元。這個事實在解密時非常重要，但密文的欄順已被 key 排序打亂，因此必須先以「原欄索引」算長度，再按「排序欄索引」分配片段。混淆這兩個順序是最常見的程式錯誤。

可用極短的 `ABCDE` 配 key `ZEBRA` 觀察邊界：只有一列時，密文其實是依 key 排序重新排列原字元；再加入第六個字元，第一原欄開始比其他欄長。將這兩例畫出來，能比長文章更快驗證你的欄長計算。也應測試 key 長度大於訊息長度，因為許多欄會是空的，但加解密仍必須正確可逆。

從攻擊角度，已知某個固定開頭（例如檔案格式或固定稱呼）可提供非常有力的欄位線索。攻擊者會嘗試不同寬度、排列候選，再檢查交錯還原後是否出現合理片段。單靠「key 是英文字母」並沒有讓欄排列難以暴力搜尋；若 key 是常見單字，字典候選更少。這正是歷史移項密碼在現代不適合作為保密工具的原因。

最後，保留所有字元是此工具的優點也是責任：換行、全形空白、連續空格都是真的資料位置。文件或作業若由不同編輯器複製，先確認格式沒有被自動整理，否則可能得到不同密文。這不是演算法隨機，而是輸入本來就不同。

若要驗證實作，將加密後每個欄段標上其原始欄號，再排序比較，能清楚看見 key 的作用只在讀取次序；字母本身從未被換掉。這種可視化方法也能防止把縱欄式誤做成凱薩或替換表。所有欄段串回原表、再逐列讀出後，原始字元序列必須一字不差地回來。

關鍵字排序應以字母的排序規則為準，而不是鍵盤位置或出現頻率；`ZEBRA` 的 A 欄最先讀正是此意。若自己用數字標號，應把最小字母標一、次小標二，並在重複字母時由左到右給號。把這個編號過程寫在表頭，是手算與教學最透明的作法。

與單純矩陣轉置不同，key 使讀欄順序成為秘密參數；但表格尺寸往往能由密文長度、已知詞或語言分數推測。若 key 長度猜對、欄順猜錯，還原文字會保留某些規律卻不通順；這是嘗試排列時常見的中間狀態，而不是另一種密碼。

縱欄式不補位的設計要求解密精確處理最後一列。這比補位版本少了一個填充歧義，但也使欄長依訊息長度而異。兩種版本都合理，重點是收發雙方和教材不能混用。

若要比較不同 key，請固定明文與格式，否則密文差異無法歸因於欄位排序。這是實驗置換密碼時最簡單也最常被忽略的控制變因。
