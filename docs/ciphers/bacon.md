# 培根密碼（Bacon Cipher）

> 分類：二元符號替換密碼。CipherTool 採 26 字母、每字母五位 A/B 群組；輸入只支援英文字母與空白。

## 歷史與二元表示的想法

培根密碼通常歸於英國哲學家 Francis Bacon 在十七世紀提出的雙字母密碼概念。它的巧思不是找一個更複雜的字母表，而是把每個字母拆成五個二元選擇：A 或 B。五個位置共有 `2⁵=32` 種組合，足以容納英文字母。歷史版本有時將 I/J 或 U/V 合併為二十四個字母，排列也可能不同；因此看到「Bacon」時不能只憑名稱假設每張表都相同。

這個二元結構很適合隱寫術。發送者可以將一段看似普通的文字排版成兩種字型、粗細、大小寫、手寫筆跡或其他可分辨的外觀，每五個可見符號實際承載一個秘密字母。例如普通字體代表 A、粗體代表 B；讀者只要知道規則就能把外觀轉回 A/B 群組。此時真正隱藏的是「有訊息存在」這件事，而不是 A/B 表本身具有強加密能力。

CipherTool 提供的是清楚可見的文字形式，而非自動把訊息藏進另一篇文章。它直接輸出 `AAAAA`、`AAAAB` 等五字元群組，便於學習二進制與字母映射。這表示輸出看起來不像一般文章，也沒有隱寫效果；它刻意把規則攤開，讓使用者能檢查每一位。

## CipherTool 的二十六字母表

工具把 A 到 Z 依索引 0 到 25 轉成五位元二進制，再把 0 寫成 A、1 寫成 B：

```text
A = 00000 = AAAAA
B = 00001 = AAAAB
C = 00010 = AAABA
...
Z = 11001 = BBAAB
```

因此加密可形式化為：先令字母索引 `n∈{0,…,25}`，取其五位二進制表示 `b₄b₃b₂b₁b₀`，再把每個 0 映射為 A、每個 1 映射為 B。解密反向進行：把 A/B 換回 0/1、讀成二進制整數，再以 0 對應 A、25 對應 Z。剩下的二進制值 26 到 31 在此二十六字母版本中沒有對應字母，所以是無效群組。

每個群組必須恰好五個 A 或 B。`AAABA` 是 C；`AAB` 太短；`AAAAZ` 含非法符號；`BBABA` 代表二十六，超出 Z，也無效。工具把群組以空白分隔，空白字元本身以獨立 `/` token 表示。這和把所有 A/B 連成一長串不同：理論上可以每五位切分，但明確分隔能降低抄寫與解碼錯位的機會。

## 範例：從文字到群組

以 `CAB` 為例，C 的索引是 2，二進制五位表示為 `00010`，得到 `AAABA`；A 是 `AAAAA`；B 是 `AAAAB`。輸出為：

```text
明文：CAB
密文：AAABA AAAAA AAAAB
```

反過來把這三組貼入 decode，結果是 `CAB`。若輸入 `A B`，輸出會是 `AAAAA / AAAAB`，`/` 是明確的單字間空白記號。解碼時每個 `/` 產生一個空格。大小寫不保留：編碼先把文字轉大寫，解碼也輸出大寫。數字、逗號、中文、emoji 和連字號不屬於可編碼輸入，會被拒絕，而不是原樣混入結果。

手算時最常犯的錯誤是把二進制位元順序倒過來。此工具使用一般從左到右的最高位到最低位書寫：B 是最右邊一位變成 B，即 `AAAAB`，不是 `BAAAA`。另一個錯誤是使用舊版二十四字母表卻期待本工具結果；在這裡 I、J、U、V 都是各自獨立的二十六個字母，請以程式定義為準。

## 在 CipherTool 中使用

於 GUI 選 Classical Cipher → Bacon Cipher。encode 需輸入英文與空白；decode 則輸入以空白分隔的五位 A/B 群組與 `/`。不需要 key，因為 A/B 對照固定。試著輸入 `HELLO`，工具會產生五組；逐組拿第一個字母做二進制換算，是檢查理解的好方法。若 GUI 顯示錯誤，先檢查是否含有標點，或解碼群組是否缺少空白分隔。

輸出可複製到筆記中，或作為另一個隱寫練習的原始 bit 流；但 CipherTool 不會自動將 A/B 轉成粗細、大小寫或字型差異。若你要製作隱寫文章，仍須自行定義載體、五個位置如何對齊、遇到標點怎麼辦，以及接收者如何識別兩種樣式。這些規格若沒有寫下來，即使雙方都知道培根密碼也未必能正確還原。

## 破解與安全限制

可見的 A/B 群組完全沒有秘密。任何人只要知道五位 A/B 對照，或觀察到其二進制模式，就能立即還原。即使隱藏在字型或大小寫中，攻擊者一旦察覺兩種樣式的規律，仍能把它們抽取為 bit 並查表。若載體文章的格式被重新排版、字型被正規化、複製貼上時大小寫改變，秘密也會直接損壞。

從統計角度，它仍是固定替換：同一原文字母總產生同一五位群組。頻率、群組重複與單字長度（若 `/` 保留）依舊會洩露語言結構。二進制外觀不會自動帶來密碼學保護；Base64、Hex、摩斯和這裡的 A/B 都是資料表示法，除非另有安全金鑰與演算法，否則不應被稱為加密保密。

培根密碼的正確學習價值在於理解資訊可由兩種狀態承載，以及編碼、隱寫、加密三者的不同。它不適合傳遞密碼、個資、金鑰或其他敏感資料，也無法偵測訊息被惡意替換。真實保密與完整性需求應使用成熟的現代加密與驗證機制。

## 常見錯誤與自我檢查

以 `CAB` 編碼，應得到 `AAABA AAAAA AAAAB`；解碼後必須回到 `CAB`。輸入 `A B` 時應看見 `/`；輸入 `AAAA` 或 `BBABA` 解碼應失敗。這些測試分別確認位元順序、空白表示、群組長度與二十六字母範圍。

## 從 A/B 到資訊表示

培根密碼是理解位元概念的好橋梁。單一 A 或 B 只攜帶一個二選一狀態，相當於一個 bit；五個狀態組合後可表示三十二種結果。因為英文字母只需要二十六種，還會有六個未使用值。現代電腦通常以八位元的 byte 處理資料，因此可表示二百五十六種值；但「把抽象符號轉成固定長度 bit 序列」的基本思考方式與培根密碼完全相通。

固定長度的優點是解碼邊界明確。假如沒有空白分組，讀者知道每五個字元就是一個字母，也仍能處理；可是只要中間漏抄一個 A 或 B，後面所有五位分組都會錯位。CipherTool 用空白分組可讓你更快檢查每格是否剛好五位，但它無法自動修復漏字或判斷原本應是哪一組。這可用來說明編碼系統中的同步問題，以及為什麼真實通訊協定常需要長度欄位、同步標記或檢查碼。

若把 A/B 藏進大小寫，必須非常小心載體的正常處理流程。許多電子郵件、網頁編輯器、社群平台或文件轉檔會自動統一字型、改寫大小寫、移除多餘空格或套用樣式；任何一種正規化都可能讓兩種狀態消失。隱寫的可靠性不只取決於密碼表，也取決於載體是否能在傳輸中保留精確格式。CipherTool 顯式輸出 A/B，正好避開這個媒介脆弱性，但同時也不再隱藏訊息存在。

有時題目會以 `0/1`、黑白、粗細、長短或兩種同義字表示 A/B。解題的第一步是先抽取出二元序列，第二步才是決定 A 是否等於 0、群組從哪裡開始、每組是否五位，以及使用哪一版字母表。若結果落在未使用值或不像自然語言，不一定表示方法錯了，可能是起點偏移、A/B 對調或版本不同；應逐項驗證，而非隨意改答案。

培根密碼沒有內建錯誤偵測。`AAAAA` 的一位被改成 `AAAAB`，A 就靜默變成 B；若整組變成未使用值，工具只能告訴你格式不合法，無法知道原字母。因此它不適合可靠資料傳輸，更不適合安全通訊。若要驗證資料是否被意外改動，應使用完整性檢查工具；若要防篡改，還需要有密鑰的認證機制。

最後，請不要把這個五位 A/B 表與使用者先前提出的 CRC 或校驗碼混在一起。培根的五位是「字母表示內容」，不是用來偵測錯誤的冗餘檢查；CRC 則以輸入資料計算檢查值，目的不同。表面都是二進制，功能卻完全不同。
