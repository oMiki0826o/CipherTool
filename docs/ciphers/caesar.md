# 凱薩密碼（Caesar Cipher）

> 分類：單表替換密碼。CipherTool 參數：`shift`，可填 0 到 25 的整數。

## 它是什麼，以及它從哪裡來

凱薩密碼是最適合用來理解「替換」概念的古典密碼。傳統說法把它和羅馬共和末期的尤利烏斯．凱薩連在一起：送信者把每個拉丁字母往字母表的固定方向挪動幾格，收信者知道相同的位移量，就能挪回原來的位置。歷史上的羅馬字母表和今天的二十六個英文字母並不完全相同，因此「凱薩當年是否正好使用現代 A 到 Z 的形式」不是重點；它的重要性在於，這個方法清楚展示了密鑰如何把同一套規則變成不同的密文。

它又叫位移密碼。假如位移量是 3，明文 `A` 會變成 `D`，`B` 變成 `E`，一路到 `X` 變成 `A`，因為字母表在尾端會繞回開頭。密碼表可以寫成兩列：上列是原字母，下列是往右平移後的字母。加密和解密不需要查詢任何秘密字典，只需要雙方同意一個小整數。也正因為密鑰空間只有二十六種狀態，凱薩密碼現在只適合教學、解謎或辨識簡單字串，完全不適合保護真正的資料。

## 核心邏輯與數學表示

先把英文字母編號。通常令 `A=0, B=1, …, Z=25`；小寫字母可先轉成同樣的索引處理，再換回小寫。令明文字母索引為 `P`，位移量為 `k`，密文字母索引為 `C`，加密公式是：

```text
C = (P + k) mod 26
```

其中 `mod 26` 表示除以二十六後取餘數，所以 25 再加 1 會得到 0，正好表現 `Z` 回到 `A`。解密是反向位移：

```text
P = (C - k) mod 26
```

在模二十六的世界裡，減去 `k` 和加上 `26-k` 是等價的；因此實作者不用真的處理負索引，只要在最後取模即可。這種「一個字母永遠替換成同一個字母」的性質，稱為單表替換。它讓原文的字母頻率、重複片段與詞長幾乎完整保留，這正是它很容易被破解的原因。

## 如何加密與解密

以明文 `HELLO, WORLD!` 和位移量 3 為例。先看 `H`：它的索引是 7，`(7+3) mod 26=10`，索引 10 是 `K`。`E` 的索引 4 會變成 7，也就是 `H`。依序處理後，得到：

```text
明文：HELLO, WORLD!
位移：3
密文：KHOOR, ZRUOG!
```

逗號、空白、驚嘆號不是英文字母，CipherTool 會原樣保留它們。這使輸出的句子形狀較容易閱讀，也意味標點和空格會洩露原文的分詞資訊。收到 `KHOOR` 時，知道 `k=3` 的人向回移三格：`K→H`、`H→E`、`O→L`，便能還原 `HELLO`。大小寫同樣會保留：`Hello` 在同一位移下會變成 `Khoor`，而不是全部強制改成大寫。

手算時最容易犯的錯是繞回規則。很多人把 `Y` 往後移三格誤寫成不存在的字母；正確順序是 `Y→Z→A→B`。另一個常見錯誤是加密時往右、解密時也往右，結果當然無法回到原文。請先固定自己的慣例：本頁和 CipherTool 將「加密」定義為索引加上 shift，解密則減去 shift。若網路題目採反方向慣例，只要把位移改成 `26-k`，結果會等價。

## 在 CipherTool 中操作

在圖形介面選擇 Classical Cipher 類別，再選 Caesar。輸入文字後，在「位移量／Shift」填入 `0` 至 `25`。選擇加密會套用公式 `P+k`；選擇解密會套用 `C-k`。輸入 `0` 是合法但沒有變化的情況，適合檢查操作流程，不是有意義的保密密鑰。程式只會替換 ASCII 的 `A-Z` 與 `a-z`；中文、數字、空白、emoji 和標點都不會改變。這一點很重要：把中文貼進去看見原文不是故障，而是目前演算法的明確處理範圍。

若你在命令列或程式碼中使用核心模組，概念上是把文字和整數 `shift` 交給 `encrypt` 或 `decrypt`。位移量超出範圍或不是整數應視為無效參數，而不是猜測使用者意思。教學練習可先用短詞，例如選 5、加密 `CODE`，再不用工具手算解回來；確認索引與繞回都正確後，再處理句子。

## 怎麼破解，以及為什麼不安全

凱薩密碼的第一種破解法根本不需要密碼學：把二十六個可能位移全部試一遍。英文句子通常在很少的嘗試後就會出現可讀單字；自動化程式可用字典分數或常見雙字母組合排序候選結果。即使不知道語言，固定替換仍保留頻率特徵：密文最常見的字母很可能對應英文常見的 `E`、`T` 或 `A`，短字和重複字也會提供線索。

更本質的問題是密鑰熵太低。二十六個選擇約等於 4.7 位元的資訊量，現代電腦瞬間就能枚舉；而且攻擊者知道演算法並不會增加工作量，因為真正未知的只有 `k`。這也能用來理解 Kerckhoffs 原則：安全性應建立在密鑰保密，而不是演算法神祕。凱薩密碼連密鑰本身都小得不堪一擊，所以不能拿來保護密碼、個資、登入權杖、交易資料或任何敏感內容。

它仍然有教學價值。你可以藉它練習模運算、觀察字元編碼與字母表索引的差異，並比較「可逆轉換」與真正安全加密之間的距離。若目標是實際保密，應選用作業系統或成熟函式庫提供的現代、經驗證加密方案，而不是加大凱薩位移、連續套用幾次，或自行和其他古典密碼拼接。

## 延伸觀察：從表格到程式

紙筆操作時，先畫二十六格圓環或兩列字母最不容易出錯；程式操作時，卻不應把二十六個對照表硬寫二十六次。把字元轉為相對於 `A` 或 `a` 的索引、加上位移、取模、再轉回字元，便能同時處理任何位移。這也解釋為何必須分開大寫與小寫的起點：Unicode 中 `A` 和 `a` 的數值不是同一個連續循環的一部分，直接在整個字元碼上加三會誤改標點，甚至跑到非字母字元。CipherTool 因而先辨識英文字母，再在各自的二十六格範圍運算。

可用下列檢查清單驗證一段練習答案。第一，字母數量應不變；第二，空格和標點的位置應不變；第三，同一個明文字母必定對到同一個密文字母；第四，用相反方向與同一 shift 處理後必須精確回到原字串。若任何一點失敗，通常是把非字母也位移、忘了取模，或把解密方向寫反。這些看似細小的邊界條件，在更複雜的密碼實作中同樣關鍵。

也可以從密文形狀做快速辨認。例如 `KHOOR` 的三個連續 `O` 對應原文的兩個連續 `L`，重複結構完全沒有被隱藏；`A` 和 `N` 在 shift 13 時形成互換，便自然連到 ROT13。若題目只說「每個字母往後固定移動」而沒有給數字，優先嘗試二十六種凱薩位移，而不是直接假定 ROT13。相反地，若同一明文字母在不同位置變成不同符號，就已經不是單純凱薩，可能是維吉尼亞、Autokey 或其他多表替換。

最後要區分「位移量」和「字母位置」。有些教材以 `A=1` 記錄字母，另一些以 `A=0`；只要公式前後一致，結果相同。CipherTool 的內部概念採 `A=0`，所以 shift 3 的範例是 `A→D`。把規則先寫清楚比死背範例更可靠，這也是閱讀任何密碼題目時應先確認的前提。

若要自我測試，請用 `XYZ xyz` 和 shift 3。正確密文必須是 `ABC abc`；再解密一次必須逐字回到 `XYZ xyz`。這個例子同時覆蓋尾端繞回與大小寫保留兩個最重要的規則。

這類短測試比只看一個 `HELLO` 範例更有價值，因為它能立刻暴露邊界條件是否正確。
